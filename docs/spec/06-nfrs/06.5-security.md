## §6.5 Security Requirements

### NFR-SEC01 — Transport Security

**Requirement**
- All network traffic must be encrypted using HTTPS
- TLS minimum: **TLS 1.2** (TLS 1.3 recommended)

---

### NFR-SEC02 — Password Security

**Requirement**
- Passwords must be **hashed**, never encrypted
- Use:
  - bcrypt (cost 12) OR Argon2id
- Password reset tokens expire after **30 minutes**
- Email verification tokens expire after **24 hours**

---

### NFR-SEC03 — Authentication & Session Security

**Requirement**
- Access token:
  - JWT, 15 minutes
- Refresh tokens:
  - opaque random string
  - stored hashed
  - rotated on use
  - revoked on logout/reset password/deactivation
- Refresh token stored as **httpOnly secure cookie** (recommended)

---

### NFR-SEC04 — Authorization & Data Isolation

**Requirement**
- Workspace isolation is absolute:
  - All workspace-scoped queries must filter by `workspace_id`
  - No cross-workspace data leakage is acceptable

**Testing requirement**
- Integration tests must validate that user in workspace A cannot access resources in workspace B, even if IDs are guessed.

---

### NFR-SEC05 — Input Validation & Sanitization

**Requirement**
- All inputs validated server-side (DTO validation)
- Sanitize user-generated content:
  - Comments and pasted editor content must be sanitized
  - Avoid storing raw HTML
- Protect against OWASP Top 10:
  - SQL injection: parameterized queries/ORM
  - XSS: sanitize + output encoding
  - CSRF: SameSite cookies + POST-only refresh endpoints; CSRF tokens in v1.1 if required
  - IDOR: enforce workspace membership on every resource fetch

---

### NFR-SEC06 — Rate Limiting

**Requirement**
- Rate limits applied to:
  - auth endpoints (strict)
  - write endpoints (moderate)
  - read endpoints (higher)
- Return `429 RATE_LIMITED` with cooldown hints.

---

### NFR-SEC07 — Audit Logging

**Requirement**
- All security-sensitive actions must be recorded in audit log (see §5.8)
- Audit logs are immutable and admin-only

---
