## §11.3 Authentication Security (v1)

### §11.3.1 Password Storage
- Use bcrypt with cost factor 12 (or Argon2id)
- Store only password hash (never plaintext)
- Enforce password policy at client + server

### §11.3.2 Session Tokens
- Access token:
  - JWT, 15 minutes
  - stored in memory client-side
- Refresh token:
  - opaque random token
  - stored as httpOnly cookie
  - stored hashed server-side
  - rotated on use
  - revoked on logout/reset/deactivation

### §11.3.3 Email Verification
- Local accounts require email verification
- Verification tokens:
  - random opaque values
  - stored hashed
  - 24h expiry
  - single-use

### §11.3.4 OAuth Security
- Google OAuth uses Authorization Code flow
- `state` param required (anti-CSRF)
- PKCE recommended if feasible
- Minimal scopes: `openid email profile`
