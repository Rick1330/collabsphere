## §7.4 Repository & Code Organization (Monorepo)

### §7.4.1 Monorepo Layout (Authoritative)

```
collabsphere/
├── apps/
│   ├── web/                      # Vite + React SPA frontend foundation on Vercel
│   ├── api/                      # NestJS backend (REST + Socket.IO)
│   ├── collab/                   # Hocuspocus collaboration server
│   └── worker/                   # BullMQ workers (email/export/cleanup)
│
├── packages/
│   ├── shared/                   # shared TS types, constants, schemas
│   └── ui/                       # (optional) shared UI components
│
├── infra/
│   ├── docker/                   # dockerfiles, compose fragments
│   └── migrations/               # (optional) ops scripts
│
├── .github/workflows/            # CI pipelines
├── docker-compose.yml
├── turbo.json
├── pnpm-workspace.yaml
└── README.md
```

Note:

- `apps/web` now contains the current Vite + React SPA foundation with `react-router-dom` as the active runtime router and Tailwind/shadcn-based UI primitives.
- The app still intentionally defers product-complete navigation, auth, and story-specific UI behavior to downstream PRJ-02 work.

### §7.4.2 Backend Module Boundaries (NestJS)

`apps/api/src/modules/*`:

- `auth`
- `users`
- `workspaces`
- `memberships` (workspace_members)
- `documents` (metadata, hierarchy, versions, export triggers)
- `tasks`
- `comments`
- `notifications`
- `activity`
- `search`
- `files` (v1.1 recommended)
- `admin`
- `common` (guards, interceptors, error handling, requestId)

**Rule:** No module directly queries another module’s tables without going through a service boundary (enforced by code review, not runtime).
