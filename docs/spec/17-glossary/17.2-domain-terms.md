## §17.2 Domain Terms

| Term | Definition | Notes / Examples |
|------|------------|------------------|
| **Workspace** | A bounded collaboration container that holds documents, tasks, files, and members. | “Project Alpha” workspace |
| **Workspace Type** | A workspace mode that changes defaults and workflows. | `professional`, `academic`, `general` |
| **Member** | A user who belongs to a workspace via `workspace_members` record. | A student in a project workspace |
| **Workspace Role** | Permission level of a member within a workspace. | Owner/Admin/Manager/Member/Viewer |
| **Owner** | The single user with full control over a workspace (including delete/transfer ownership). | “Supervisor” label in academic mode |
| **Admin (Workspace)** | Manages members and workspace settings but cannot delete workspace. | Teaching Assistant, Engineering Manager |
| **Manager** | Manages work execution: assigns tasks, reviews submissions, sees analytics. | Tech Lead, Project Lead |
| **Viewer** | Read-only role; may be allowed to comment on documents depending on settings. | Stakeholder, External reviewer |
| **Invitation** | A time-limited token allowing a user with a specific email to join a workspace. | Expires after 7 days |
| **Template** | A predefined structure that generates workspace folders/documents or document content. | “Senior Project” workspace template |
| **Workspace Template** | Template that creates an entire workspace structure. | Folders + starter docs + task columns |
| **Document Template** | Template that creates a single document outline/content. | SRS, PRD, Thesis Outline |
| **Document** | A collaborative rich-text artifact stored as CRDT state. | “Requirements”, “Architecture” |
| **Folder** | A container node for organizing documents within a workspace hierarchy. | “Chapter 1”, “Meetings” |
| **Task** | A unit of work with assignment, priority, due date, and status. | “Implement login page” |
| **Kanban Board** | Column-based visualization of tasks by status. | To Do → In Progress → Review → Done |
| **Task Column** | A display column mapped to a canonical task status. | Column “Testing” → status `in_review` |
| **Comment Thread** | A discussion container attached to a document or task, with multiple comments and a resolved status. | Inline comment on a paragraph |
| **Comment** | A single message within a thread. | “Please clarify this section” |
| **Mention** | A reference to a user inside a comment that triggers a notification. | “@Jane please review” |
| **Notification** | A user-facing alert about an event. | Task assignment notification |
| **Activity Event** | A workspace-scoped, user-facing timeline entry of meaningful events. | “Bob completed task X” |
| **Audit Log** | A security-focused immutable log of sensitive actions. | Failed logins, role changes |
| **Submission** | Academic workflow action: submitting a document for supervisor review. | Draft → Submitted |
| **Review** | Supervisor decision on a submission: approved or changes requested. | Requires note for changes |
| **Export** | Converting a document/workspace to PDF/Markdown output. | Export to PDF for submission |
| **Attachment** | A file linked to a task or document. | “diagram.png” attached to task |
| **Soft Delete** | Marking a record deleted via `deleted_at` rather than removing it immediately. | Retained for 30–90 days |
