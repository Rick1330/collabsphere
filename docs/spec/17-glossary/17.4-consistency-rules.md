## §17.4 Consistency Rules (Must Follow)

1. Use “Workspace” (not “Project”) as the primary container term in product and code.
2. Use “Member” for workspace membership; “User” for global identity.
3. Use canonical statuses:
   - tasks: `todo`, `in_progress`, `in_review`, `done` (and optional backlog)
   - documents: `draft`, `submitted`, `changes_requested`, `approved`
4. Use “Activity” for user-facing timeline, “Audit Log” for security log.
5. Use “Template” for any prebuilt structure; specify “Workspace Template” vs “Document Template” explicitly.
6. Avoid synonyms across the codebase (e.g., do not use “owner” and “lead” interchangeably unless explicitly mapped via role labels).
