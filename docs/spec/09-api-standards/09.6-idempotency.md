## §9.6 Idempotency (P1)

### §9.6.1 Why
Users may click submit multiple times, network retries occur, and duplicate creates are dangerous for:
- workspace creation
- document creation
- task creation
- exports
- invitations

### §9.6.2 Standard
For POST endpoints that create resources, support:

- Header: `X-Idempotency-Key: <uuid>`

Behavior:
- If same key is reused by same user within a defined TTL (e.g., 24h):
  - return the original response
  - do not create a duplicate resource

Implementation:
- Store idempotency keys in DB (optional) or Redis (acceptable)
- Keyed by `(userId, endpoint, idempotencyKey)`
