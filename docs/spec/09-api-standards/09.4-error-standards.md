## §9.4 Error Standards (Authoritative)

### §9.4.1 Error Envelope

```json
{
  "error": {
    "code": "VALIDATION_ERROR",
    "message": "Title is required",
    "details": [
      { "field": "title", "message": "Title is required", "rule": "isNotEmpty" }
    ],
    "requestId": "req_abc123",
    "timestamp": "2025-07-17T12:00:00Z"
  }
}
```

### §9.4.2 Error Rules

- `code` is stable and machine-readable
- `message` is human-readable
- `details` is optional, used for validation errors
- `requestId` must always be present
- Never return stack traces
- Never leak internal IDs, SQL statements, or secrets
