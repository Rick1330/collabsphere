## §8.3 Core Entities — Users & Authentication

### §8.3.1 Table: `users`

**Purpose:** Stores platform user identities and profiles.

```sql
CREATE TABLE users (
  id                 uuid PRIMARY KEY DEFAULT gen_random_uuid(),
  email              citext NOT NULL,
  full_name          varchar(200) NOT NULL,
  avatar_url         varchar(500),
  bio                varchar(500),

  global_role        varchar(20) NOT NULL DEFAULT 'USER',          -- USER | ADMIN
  auth_provider      varchar(20) NOT NULL DEFAULT 'local',         -- local | google
  auth_provider_id   varchar(255),                                 -- google 'sub'

  password_hash      varchar(255),                                 -- null for OAuth-only
  is_verified        boolean NOT NULL DEFAULT false,
  is_active          boolean NOT NULL DEFAULT true,

  last_login_at      timestamptz,
  password_changed_at timestamptz,

  created_at         timestamptz NOT NULL DEFAULT now(),
  updated_at         timestamptz NOT NULL DEFAULT now(),
  deleted_at         timestamptz
);

-- Case-insensitive uniqueness for active users
CREATE UNIQUE INDEX uq_users_email_active
  ON users(email)
  WHERE deleted_at IS NULL;

-- Provider uniqueness (only when provider_id exists)
CREATE UNIQUE INDEX uq_users_provider_id_active
  ON users(auth_provider, auth_provider_id)
  WHERE auth_provider_id IS NOT NULL AND deleted_at IS NULL;

CREATE INDEX idx_users_global_role
  ON users(global_role)
  WHERE deleted_at IS NULL;

CREATE INDEX idx_users_created_at
  ON users(created_at DESC);
```

**Rules**
- Local users:
  - `auth_provider = 'local'`
  - `password_hash IS NOT NULL`
  - `is_verified` starts false until email verification
- Google users:
  - `auth_provider = 'google'`
  - `auth_provider_id IS NOT NULL`
  - `password_hash IS NULL`
  - `is_verified = true`

### §8.3.2 Table: `refresh_tokens`

**Purpose:** Stores hashed refresh tokens for session persistence and rotation.

```sql
CREATE TABLE refresh_tokens (
  id                 uuid PRIMARY KEY DEFAULT gen_random_uuid(),
  user_id            uuid NOT NULL REFERENCES users(id),

  token_hash         char(64) NOT NULL,                            -- sha256 hex
  created_at         timestamptz NOT NULL DEFAULT now(),
  expires_at         timestamptz NOT NULL,

  revoked_at         timestamptz,
  replaced_by_token_id uuid REFERENCES refresh_tokens(id),

  ip_address         varchar(64),
  user_agent         text
);

CREATE UNIQUE INDEX uq_refresh_tokens_token_hash
  ON refresh_tokens(token_hash);

CREATE INDEX idx_refresh_tokens_user_expires
  ON refresh_tokens(user_id, expires_at DESC);

CREATE INDEX idx_refresh_tokens_user_active
  ON refresh_tokens(user_id)
  WHERE revoked_at IS NULL;
```

**Rotation rule**
- On refresh:
  - old token row gets `revoked_at = now()`
  - new row inserted
  - old row’s `replaced_by_token_id` points to new row

### §8.3.3 Table: `email_verification_tokens`

**Purpose:** Single-use tokens for verifying local email accounts.

```sql
CREATE TABLE email_verification_tokens (
  id          uuid PRIMARY KEY DEFAULT gen_random_uuid(),
  user_id     uuid NOT NULL REFERENCES users(id),
  token_hash  char(64) NOT NULL,
  expires_at  timestamptz NOT NULL,
  used_at     timestamptz,
  created_at  timestamptz NOT NULL DEFAULT now()
);

CREATE UNIQUE INDEX uq_email_verification_token_hash
  ON email_verification_tokens(token_hash);

CREATE INDEX idx_email_verification_user
  ON email_verification_tokens(user_id, created_at DESC);
```

**Notes**
- Store only `token_hash` (sha256 of plaintext token).
- Expiry default: 24 hours.

### §8.3.4 Table: `password_reset_tokens`

**Purpose:** Single-use tokens for password reset flow (local auth).

```sql
CREATE TABLE password_reset_tokens (
  id          uuid PRIMARY KEY DEFAULT gen_random_uuid(),
  user_id     uuid NOT NULL REFERENCES users(id),
  token_hash  char(64) NOT NULL,
  expires_at  timestamptz NOT NULL,
  used_at     timestamptz,
  created_at  timestamptz NOT NULL DEFAULT now()
);

CREATE UNIQUE INDEX uq_password_reset_token_hash
  ON password_reset_tokens(token_hash);

CREATE INDEX idx_password_reset_user
  ON password_reset_tokens(user_id, created_at DESC);
```

**Expiry default:** 30 minutes.

### §8.3.5 Cascade / Deletion Policy (Auth & Users)

#### When user is soft-deleted (`users.deleted_at` set)
- Revoke all refresh tokens (`refresh_tokens.revoked_at = now()`)
- Do not delete workspaces/content immediately (data retention policy applies)
- Display name in activity/comments becomes “Deleted user” (cache full_name for display)

#### When user is hard-purged (retention job)
- Hard delete user
- Dependent records must be handled explicitly:
  - activity and audit logs retain `actor_email`/denormalized fields
  - comments retain author label as “Deleted user” (store author snapshot fields if needed)

> Implementation note: for simplicity in v1, prefer **soft delete only** and do not implement hard purge until v1.1/v2.
