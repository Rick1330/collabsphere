# §8 — Data Model & Database Design (PostgreSQL)

## §8.1 Overview

CollabSphere uses **PostgreSQL 16** as the primary source of truth for all persistent data (users, workspaces, documents metadata, tasks, comments, notifications, activity, audit logs, templates, etc.).

### §8.1.1 Design Goals
- **Strict workspace isolation**: all workspace-scoped tables include `workspace_id` and all queries must scope by it.
- **Soft delete by default**: user-facing entities use `deleted_at` to avoid destructive deletes.
- **Performance-ready**: indexes are defined for high-frequency access patterns (unread counts, feeds, lists).
- **Future-proof**: polymorphic relations (comments, attachments) are designed to support expansion.
- **CRDT-compatible**: document content is stored as **Yjs binary state**, not plain text.

## §8.1.2 Database Conventions (Authoritative)

### IDs
- All primary keys are UUIDs.
- UUID generation:
  - Enable `pgcrypto` and use `gen_random_uuid()`.

```sql
CREATE EXTENSION IF NOT EXISTS pgcrypto;
```

### Timestamps
- Use `timestamptz` everywhere (UTC).
- Standard fields:
  - `created_at timestamptz not null default now()`
  - `updated_at timestamptz not null default now()`
  - `deleted_at timestamptz null` (soft delete)

### Case-insensitive emails
Use `citext` to enforce case-insensitive uniqueness on emails.

```sql
CREATE EXTENSION IF NOT EXISTS citext;
```

### Soft delete rule
- Rows with `deleted_at IS NOT NULL` are considered deleted and must be excluded from standard queries.
- Hard deletes are allowed only for:
  - ephemeral tokens (verification/reset) after expiry
  - purge jobs (retention cleanup)
  - internal tables where soft delete is unnecessary

### Workspace scoping rule
- Any table representing workspace-owned data must include:
  - `workspace_id uuid not null references workspaces(id)`
- Authorization checks must ensure the requesting user is a member of that workspace.
