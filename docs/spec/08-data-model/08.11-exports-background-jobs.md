# §8.11 Exports & Background Jobs (Persistence)

## §8.11.1 Overview

Exports (PDF/Markdown) and other background work (email delivery, cleanup tasks, indexing) must run asynchronously for reliability and performance.

BullMQ uses Redis as the job queue. Most jobs do not require DB persistence beyond BullMQ’s internal state; however, **export jobs require user-facing tracking** and download URLs, so we persist them.

**Priority:**
- P1: Export jobs table (PDF/Markdown exports)
- P2: Email job tracking table (optional; helpful for debugging)
- P2: Cleanup job state (optional)

---

## §8.11.2 Table: `export_jobs`

**Purpose:** Tracks export requests and provides a stable job id for clients to poll.

```sql
CREATE TABLE export_jobs (
  id              uuid PRIMARY KEY DEFAULT gen_random_uuid(),
  workspace_id     uuid NOT NULL REFERENCES workspaces(id),
  requested_by     uuid NOT NULL REFERENCES users(id),

  resource_type    varchar(40) NOT NULL,          -- document | workspace (workspace export v1.1+)
  resource_id      uuid NOT NULL,

  format           varchar(20) NOT NULL,          -- pdf | markdown

  status           varchar(20) NOT NULL DEFAULT 'queued', -- queued|processing|ready|failed
  error_message    text,

  -- Output location (could be file record or direct storage key)
  output_file_id   uuid,                           -- optional FK to files(id) if you store export outputs as files
  output_storage_key varchar(500),                 -- optional if stored directly in S3

  created_at       timestamptz NOT NULL DEFAULT now(),
  updated_at       timestamptz NOT NULL DEFAULT now(),
  completed_at     timestamptz,
  deleted_at       timestamptz
);

CREATE INDEX idx_export_jobs_requester_created
  ON export_jobs(requested_by, created_at DESC)
  WHERE deleted_at IS NULL;

CREATE INDEX idx_export_jobs_workspace_created
  ON export_jobs(workspace_id, created_at DESC)
  WHERE deleted_at IS NULL;

CREATE INDEX idx_export_jobs_status
  ON export_jobs(status, created_at DESC)
  WHERE deleted_at IS NULL;
```

**Rules**
- Exports are workspace-scoped and must validate permissions at request time.
- Download URL issuance must validate requester access again (defense-in-depth).

Retention:
- Keep export jobs for 30 days (configurable).
- Output files retained per policy (if stored).

## §8.11.3 Optional Table: `email_delivery_log` (P2)

**Purpose:** Debugging and transparency for email sending (instant + digest).

```sql
CREATE TABLE email_delivery_log (
  id              uuid PRIMARY KEY DEFAULT gen_random_uuid(),
  user_id         uuid REFERENCES users(id),
  to_email        citext NOT NULL,

  template_key    varchar(120) NOT NULL,          -- e.g., "workspace_invite"
  provider        varchar(50) NOT NULL,           -- resend|sendgrid
  provider_message_id varchar(255),

  status          varchar(20) NOT NULL,           -- queued|sent|failed
  error_message   text,

  created_at      timestamptz NOT NULL DEFAULT now(),
  updated_at      timestamptz NOT NULL DEFAULT now()
);

CREATE INDEX idx_email_delivery_user_created
  ON email_delivery_log(user_id, created_at DESC);

CREATE INDEX idx_email_delivery_status
  ON email_delivery_log(status, created_at DESC);
```

## §8.11.4 Cleanup/Retention Jobs (Implementation Note)

Retention policies (documents/tasks/workspaces/notifications) can be implemented using:
- scheduled BullMQ jobs (cron-like repeatable jobs)

No DB table is required unless you want job state visibility.

v1 minimal:
- A scheduled worker runs:
  - purge expired tokens (verification/reset)
  - expire invitations
  - purge soft-deleted entities past retention windows
  - purge old notifications beyond limits
  - cleanup orphaned pending file uploads (v1.1)
