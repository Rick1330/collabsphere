## §8.4 Indexing & Query Patterns (Auth)

### High-frequency queries
1. **Login**: `users` by email
2. **Refresh**: `refresh_tokens` by token_hash
3. **Email verification**: token table by token_hash
4. **Admin user list**: users filtered by status/provider/role with pagination

Indexes above are designed to support those patterns efficiently.

# §8.4 Workspaces, Memberships, Settings, Invitations

## §8.4.1 Table: `workspaces`

**Purpose:** Root container for collaboration.

```sql
CREATE TABLE workspaces (
  id           uuid PRIMARY KEY DEFAULT gen_random_uuid(),
  name         varchar(60) NOT NULL,
  description  varchar(280),
  icon         varchar(16),

  type         varchar(20) NOT NULL,            -- professional | academic | general
  status       varchar(20) NOT NULL DEFAULT 'active', -- active | archived

  owner_id     uuid NOT NULL REFERENCES users(id),

  created_at   timestamptz NOT NULL DEFAULT now(),
  updated_at   timestamptz NOT NULL DEFAULT now(),
  deleted_at   timestamptz
);

CREATE INDEX idx_workspaces_owner_created
  ON workspaces(owner_id, created_at DESC)
  WHERE deleted_at IS NULL;

CREATE INDEX idx_workspaces_type_status
  ON workspaces(type, status)
  WHERE deleted_at IS NULL;

CREATE INDEX idx_workspaces_updated
  ON workspaces(updated_at DESC)
  WHERE deleted_at IS NULL;
```

**Constraints & Rules**
- `owner_id` must always reference a valid active user (enforced by application logic).
- Workspace name uniqueness:
  - v1 recommendation: unique per owner among non-deleted workspaces (optional).
  - If enforced, implement a partial unique index on `(owner_id, name)` where `deleted_at IS NULL`.

## §8.4.2 Table: `workspace_members`

**Purpose:** Many-to-many relationship between users and workspaces, carrying per-workspace role.

```sql
CREATE TABLE workspace_members (
  id              uuid PRIMARY KEY DEFAULT gen_random_uuid(),
  workspace_id     uuid NOT NULL REFERENCES workspaces(id),
  user_id          uuid NOT NULL REFERENCES users(id),

  role             varchar(20) NOT NULL,        -- OWNER | ADMIN | MANAGER | MEMBER | VIEWER

  joined_at        timestamptz NOT NULL DEFAULT now(),
  left_at          timestamptz,
  is_active        boolean NOT NULL DEFAULT true,

  last_accessed_at timestamptz,

  created_at       timestamptz NOT NULL DEFAULT now(),
  updated_at       timestamptz NOT NULL DEFAULT now(),
  deleted_at       timestamptz
);

-- One active membership per user per workspace
CREATE UNIQUE INDEX uq_workspace_members_active
  ON workspace_members(workspace_id, user_id)
  WHERE is_active = true AND deleted_at IS NULL;

CREATE INDEX idx_workspace_members_workspace_role
  ON workspace_members(workspace_id, role)
  WHERE deleted_at IS NULL;

CREATE INDEX idx_workspace_members_user
  ON workspace_members(user_id, last_accessed_at DESC)
  WHERE deleted_at IS NULL;
```

### Ownership Invariant
- Exactly **one** active `OWNER` per workspace at all times.
- Enforced by application logic (and optionally by a partial unique index):

```sql
CREATE UNIQUE INDEX uq_workspace_single_owner
  ON workspace_members(workspace_id)
  WHERE role = 'OWNER' AND is_active = true AND deleted_at IS NULL;
```

> Note: If you add this index, ownership transfer must be done transactionally (set new owner first then demote old owner or vice versa with deferrable constraint logic).

## §8.4.3 Table: `workspace_settings`

**Purpose:** Stores workspace feature flags and UI configuration (including role label mapping).

```sql
CREATE TABLE workspace_settings (
  workspace_id  uuid PRIMARY KEY REFERENCES workspaces(id),
  settings      jsonb NOT NULL DEFAULT '{}'::jsonb,

  created_at    timestamptz NOT NULL DEFAULT now(),
  updated_at    timestamptz NOT NULL DEFAULT now()
);

-- Example settings JSON shape (documented; not enforced by DB):
-- {
--   "submissionWorkflowEnabled": true,
--   "allowViewerCommentsOnDocs": true,
--   "allowViewerCommentsOnTasks": false,
--   "allowViewerExport": false,
--   "roleLabels": {
--     "OWNER": "Supervisor",
--     "ADMIN": "Teaching Assistant",
--     "MANAGER": "Project Lead",
--     "MEMBER": "Student",
--     "VIEWER": "Reviewer"
--   }
-- }
```

**Rules**
- Default settings depend on workspace type and template.
- Settings are read frequently; keep JSON small and stable.
- Use JSON schema validation at application layer.

## §8.4.4 Table: `invitations`

**Purpose:** Email-based invites to join a workspace.

```sql
CREATE TABLE invitations (
  id               uuid PRIMARY KEY DEFAULT gen_random_uuid(),
  workspace_id      uuid NOT NULL REFERENCES workspaces(id),

  invited_email     citext NOT NULL,
  role              varchar(20) NOT NULL,           -- role to assign on accept

  token_hash        char(64) NOT NULL,              -- sha256 token
  status            varchar(20) NOT NULL DEFAULT 'pending', -- pending|accepted|expired|revoked

  invited_by_user_id uuid NOT NULL REFERENCES users(id),
  accepted_by_user_id uuid REFERENCES users(id),

  expires_at        timestamptz NOT NULL,
  accepted_at       timestamptz,

  created_at        timestamptz NOT NULL DEFAULT now(),
  updated_at        timestamptz NOT NULL DEFAULT now(),
  deleted_at        timestamptz
);

CREATE UNIQUE INDEX uq_invitations_token_hash
  ON invitations(token_hash);

CREATE INDEX idx_invitations_workspace_status
  ON invitations(workspace_id, status, expires_at)
  WHERE deleted_at IS NULL;

CREATE INDEX idx_invitations_email
  ON invitations(invited_email, status, expires_at)
  WHERE deleted_at IS NULL;
```

**Rules**
- Invitations are email-bound in v1: only a user with matching email can accept.
- Default expiry: 7 days.
- When a new invite is created for same workspace + email:
  - recommended: revoke any existing pending invite(s) and create a new one.

## §8.4.5 Workspace Isolation & Query Guardrails

All workspace-scoped queries must include:
- `workspace_id = :workspaceId`
- and must validate membership:
  - `exists workspace_members where user_id = :userId and workspace_id = :workspaceId and is_active=true`

**Implementation rule**
- Every workspace-scoped controller route must accept workspaceId in path.
- Every service method must accept workspaceId explicitly (no hidden global context).

## §8.4.6 Soft Delete & Retention (Workspaces)

- When workspace is deleted:
  - set `workspaces.deleted_at = now()`
  - set `workspaces.status` can remain (optional)
  - access to deleted workspace returns 404

Retention (default):
- workspace soft deleted retained for 90 days
- purge job permanently deletes after retention
- purge should cascade delete or mark related rows deleted to preserve referential integrity
