## §8.2 Enumerations (Canonical)

> Implementation note: You may use PostgreSQL enums or Prisma enums. This document defines the canonical set; implementation must match.

### Global-level enums
- `global_role`: `USER`, `ADMIN`
- `auth_provider`: `local`, `google`

### Workspace-level enums
- `workspace_type`: `professional`, `academic`, `general`
- `workspace_role`: `OWNER`, `ADMIN`, `MANAGER`, `MEMBER`, `VIEWER`
- `workspace_status`: `active`, `archived`

### Document-level enums
- `document_status`: `draft`, `submitted`, `changes_requested`, `approved`, `archived`

### Task-level enums
- `task_status`: `backlog`, `todo`, `in_progress`, `in_review`, `done`
- `task_priority`: `low`, `medium`, `high`, `urgent`

### Notification enums
- `notification_type`: stored as string keys (e.g., `task.assigned`, `document.mention`) to remain extensible
- `resource_type`: `workspace`, `document`, `task`, `comment_thread`, `file`, `export`

### Invitation enums
- `invitation_status`: `pending`, `accepted`, `expired`, `revoked`

### File enums (v1.1+)
- `file_status`: `pending`, `uploaded`, `ready`, `failed`, `deleted`
- `storage_provider`: `s3`

### Comment enums
- `comment_target_type`: `document`, `task`
- `comment_thread_status`: `open`, `resolved`
