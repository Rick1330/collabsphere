# §8.7 Comments, Comment Threads, Mentions (Polymorphic Targets)

## §8.7.1 Design Notes

Comments must support:
- threaded discussions
- resolving threads
- polymorphic targets:
  - document (inline/general)
  - task
- mentions (`@user`) with notification fanout

To keep the model clean:
- **comment_threads** represent the discussion container anchored to a target
- **comments** are messages within a thread
- **comment_mentions** link comments to mentioned users

---

## §8.7.2 Table: `comment_threads`

**Purpose:** Represents a thread attached to a document or task, optionally anchored to a document selection.

```sql
CREATE TABLE comment_threads (
  id            uuid PRIMARY KEY DEFAULT gen_random_uuid(),
  workspace_id   uuid NOT NULL REFERENCES workspaces(id),

  target_type    varchar(20) NOT NULL,         -- document | task
  target_id      uuid NOT NULL,

  -- For document inline comments only (optional):
  anchor         jsonb,                         -- best-effort pointer (quote/hash/headingPath)

  status         varchar(20) NOT NULL DEFAULT 'open',  -- open | resolved
  resolved_by    uuid REFERENCES users(id),
  resolved_at    timestamptz,

  created_by     uuid NOT NULL REFERENCES users(id),

  created_at     timestamptz NOT NULL DEFAULT now(),
  updated_at     timestamptz NOT NULL DEFAULT now(),
  deleted_at     timestamptz
);

CREATE INDEX idx_comment_threads_target
  ON comment_threads(workspace_id, target_type, target_id, created_at DESC)
  WHERE deleted_at IS NULL;

CREATE INDEX idx_comment_threads_status
  ON comment_threads(workspace_id, status, created_at DESC)
  WHERE deleted_at IS NULL;
```

**Rules**
- `target_id` references either `documents.id` or `tasks.id` based on `target_type`.
- DB cannot enforce polymorphic FK directly; enforce in service layer.
- For inline document comments in v1, `anchor` is populated; for general document comments, `anchor` remains null.

## §8.7.3 Table: `comments`

**Purpose:** Individual messages in a comment thread.

```sql
CREATE TABLE comments (
  id            uuid PRIMARY KEY DEFAULT gen_random_uuid(),
  workspace_id   uuid NOT NULL REFERENCES workspaces(id),

  thread_id      uuid NOT NULL REFERENCES comment_threads(id),

  author_id      uuid REFERENCES users(id),
  author_name_snapshot varchar(200) NOT NULL,   -- denormalized for “deleted user” display
  author_avatar_snapshot varchar(500),

  content        jsonb NOT NULL,                -- Tiptap JSON for rich comment content
  content_plaintext text NOT NULL DEFAULT '',   -- derived for search / snippets (optional v1.1)

  is_deleted     boolean NOT NULL DEFAULT false,
  deleted_at     timestamptz,

  created_at     timestamptz NOT NULL DEFAULT now(),
  updated_at     timestamptz NOT NULL DEFAULT now()
);

CREATE INDEX idx_comments_thread_created
  ON comments(thread_id, created_at ASC);

CREATE INDEX idx_comments_workspace_created
  ON comments(workspace_id, created_at DESC);
```

**Deletion strategy**
- Prefer soft-delete message content in-place:
  - set `is_deleted=true`
  - replace content with a minimal “deleted” marker in application logic
  - keep row for thread continuity

## §8.7.4 Table: `comment_mentions`

**Purpose:** Records which users were mentioned in a comment.

```sql
CREATE TABLE comment_mentions (
  id            uuid PRIMARY KEY DEFAULT gen_random_uuid(),
  workspace_id   uuid NOT NULL REFERENCES workspaces(id),

  comment_id     uuid NOT NULL REFERENCES comments(id),
  mentioned_user_id uuid NOT NULL REFERENCES users(id),

  created_at     timestamptz NOT NULL DEFAULT now()
);

CREATE UNIQUE INDEX uq_comment_mentions_unique
  ON comment_mentions(comment_id, mentioned_user_id);

CREATE INDEX idx_comment_mentions_user
  ON comment_mentions(mentioned_user_id, created_at DESC);
```

## §8.7.5 Integrity & Cascade Rules

### When a document is deleted
- comment threads targeting it remain during retention
- UI shows “Document deleted” placeholder
- purge job deletes comment_threads/comments after retention if document is purged

### When a task is deleted
- same behavior as documents

### When a user is deleted
- `author_id` may become null (if hard-purged)
- `author_name_snapshot` and `author_avatar_snapshot` preserve display

### When thread is resolved
- set:
  - `status='resolved'`
  - `resolved_by`, `resolved_at`
- `updated_at` updated
