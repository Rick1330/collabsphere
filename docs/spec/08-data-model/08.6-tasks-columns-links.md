# §8.6 Tasks, Task Columns, Task Search

## §8.6.1 Table: `task_columns`

**Purpose:** Defines the Kanban board columns for a workspace. Columns map display names to canonical statuses.

```sql
CREATE TABLE task_columns (
  id           uuid PRIMARY KEY DEFAULT gen_random_uuid(),
  workspace_id  uuid NOT NULL REFERENCES workspaces(id),

  name         varchar(50) NOT NULL,              -- display name (e.g., "Review")
  status       varchar(30) NOT NULL,              -- canonical status (e.g., "in_review")

  position     numeric(20,10) NOT NULL,           -- ordering in board
  is_hidden    boolean NOT NULL DEFAULT false,    -- P2 feature

  created_at   timestamptz NOT NULL DEFAULT now(),
  updated_at   timestamptz NOT NULL DEFAULT now(),
  deleted_at   timestamptz
);

CREATE INDEX idx_task_columns_workspace_pos
  ON task_columns(workspace_id, position)
  WHERE deleted_at IS NULL;

CREATE INDEX idx_task_columns_workspace_status
  ON task_columns(workspace_id, status)
  WHERE deleted_at IS NULL;
```

**Rules**
- Columns are provisioned via workspace template on workspace creation.
- v1 UI may treat columns as read-only; still store them for flexibility.
- `status` must be one of canonical task statuses.

## §8.6.2 Table: `tasks`

**Purpose:** Stores tasks and their workflow state.

```sql
CREATE TABLE tasks (
  id            uuid PRIMARY KEY DEFAULT gen_random_uuid(),
  workspace_id   uuid NOT NULL REFERENCES workspaces(id),

  title         varchar(200) NOT NULL,
  description   text,                                -- plain text only in v1

  status        varchar(30) NOT NULL DEFAULT 'todo',       -- backlog|todo|in_progress|in_review|done
  priority      varchar(20) NOT NULL DEFAULT 'medium',     -- low|medium|high|urgent

  assignee_id   uuid REFERENCES users(id),
  reporter_id   uuid NOT NULL REFERENCES users(id),

  due_date      date,
  labels        text[] NOT NULL DEFAULT '{}'::text[],

  position      numeric(20,10) NOT NULL,                   -- ordering in column

  -- Derived search
  search_vector tsvector,

  created_at    timestamptz NOT NULL DEFAULT now(),
  updated_at    timestamptz NOT NULL DEFAULT now(),
  deleted_at    timestamptz
);

CREATE INDEX idx_tasks_workspace_status_pos
  ON tasks(workspace_id, status, position)
  WHERE deleted_at IS NULL;

CREATE INDEX idx_tasks_workspace_assignee_due
  ON tasks(workspace_id, assignee_id, due_date)
  WHERE deleted_at IS NULL;

CREATE INDEX idx_tasks_workspace_updated
  ON tasks(workspace_id, updated_at DESC)
  WHERE deleted_at IS NULL;

CREATE INDEX idx_tasks_search_vector
  ON tasks
  USING GIN (search_vector);
```

### Maintaining `search_vector`
Optionally use trigger:

```sql
CREATE FUNCTION tasks_search_vector_update() RETURNS trigger AS $$
begin
  new.search_vector :=
    setweight(to_tsvector('english', coalesce(new.title,'')), 'A') ||
    setweight(to_tsvector('english', coalesce(new.description,'')), 'B');
  return new;
end
$$ LANGUAGE plpgsql;

CREATE TRIGGER trg_tasks_search_vector
BEFORE INSERT OR UPDATE OF title, description
ON tasks
FOR EACH ROW EXECUTE FUNCTION tasks_search_vector_update();
```

## §8.6.3 Task Ownership & Membership Integrity

### Rules
- `assignee_id` must be a workspace member (enforced by application validation).
- If a user is removed from workspace:
  - tasks assigned to them must be set `assignee_id = null` (recommended).
  - emit domain event: `task.unassigned_due_to_member_removal`

This can be done:
- in application service on member removal
- not via DB constraints (because membership is in another table)

---

## §8.6.4 Soft Delete & Retention (Tasks)

- soft delete: `deleted_at = now()`
- retention default: 30 days
- purge job permanently deletes tasks after retention
- associated task comments should be purged or retained consistently (see comments section)

## §8.6.5 Document ↔ Task Links

### §8.6.5.1 Table: `task_document_links`

**Purpose:** Stores links between tasks and documents with optional anchors.

```sql
CREATE TABLE task_document_links (
  id           uuid PRIMARY KEY DEFAULT gen_random_uuid(),
  workspace_id  uuid NOT NULL REFERENCES workspaces(id),

  task_id      uuid NOT NULL REFERENCES tasks(id),
  document_id  uuid NOT NULL REFERENCES documents(id),

  anchor       jsonb,                         -- optional anchor data
  created_by   uuid NOT NULL REFERENCES users(id),

  created_at   timestamptz NOT NULL DEFAULT now(),
  deleted_at   timestamptz
);

CREATE INDEX idx_task_doc_links_task
  ON task_document_links(workspace_id, task_id, created_at DESC)
  WHERE deleted_at IS NULL;

CREATE INDEX idx_task_doc_links_doc
  ON task_document_links(workspace_id, document_id, created_at DESC)
  WHERE deleted_at IS NULL;
```

**Rules**
- `task_id` and `document_id` must belong to same workspace (enforced by service).
- v1 can enforce “max 1 link per task” in application logic if desired, but schema supports many.
