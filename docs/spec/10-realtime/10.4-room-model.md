## §10.4 Room Model (Socket.IO)

### §10.4.1 Room Types

| Room Pattern | Example | Who Joins | Purpose |
|-------------|---------|----------|---------|
| `user:<userId>` | `user:abc` | All sockets of that user | Personal notifications, preference updates |
| `workspace:<workspaceId>` | `workspace:ws1` | Sockets currently viewing that workspace | Task/activity broadcasts |
| `task:<taskId>` (optional) | `task:t1` | Users viewing a task detail | Task comment stream, detail updates |
| `doc-meta:<documentId>` (optional) | `doc-meta:d1` | Users viewing doc page | Document metadata changes (lock/status) |

### §10.4.2 Join Rules
- On app load:
  - join `user:<userId>`
- On entering a workspace route:
  - join `workspace:<workspaceId>`
- On leaving workspace route:
  - leave workspace room
- On opening task detail:
  - join `task:<taskId>` (optional)

Server must validate workspace membership for any join request.
