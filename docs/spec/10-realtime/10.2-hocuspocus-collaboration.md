## §10.2 Realtime System A — Document Collaboration (Hocuspocus)

### §10.2.1 Responsibilities
- Sync Yjs updates between clients editing the same document
- Provide awareness state:
  - presence (who is viewing)
  - cursors (where they are)
  - optional typing indicators
- Persist Yjs state to PostgreSQL via hooks
- Enforce authorization:
  - only workspace members can join document rooms
  - only users with edit permission can publish updates

### §10.2.2 WebSocket Endpoint
- `wss://api.collabsphere.io/collaboration`

### §10.2.3 Document Room Naming
- `doc:<documentId>`

### §10.2.4 Authentication
- Client provides JWT access token on connect:
  - connection params or `Authorization` header
- Server validates JWT:
  - signature + expiry
  - `users.is_active = true`
  - `users.deleted_at is null`

### §10.2.5 Authorization
On each document connection:
- load document metadata from DB:
  - workspaceId
  - status
  - isLocked
  - deletedAt
- verify workspace membership for user
- compute effective permission:
  - read-only allowed for Viewer+
- edit allowed for Member+ *and* document not locked/submitted/approved (locked docs are editable only by lock owner or Admin/Owner)

**Enforcement**
- If user has read-only access:
  - allow connection and sync
  - reject update messages (server side)

### §10.2.6 Persistence Hooks (Authoritative)
Hocuspocus hooks:
- `onLoadDocument`:
  - fetch `documents.content_yjs`
  - return as initial state
- `onStoreDocument`:
  - persist updated Yjs state into `documents.content_yjs`
  - update `documents.updated_at`, `updated_by`
  - update `documents.content_plaintext` (optional synchronous; recommended async)
- `onConnect` / `onDisconnect`:
  - update presence tracking (optional)
  - emit internal events: `document.collaboration_joined/left`

### §10.2.7 Collaboration Failure Modes
| Failure | Expected Behavior |
|---------|-------------------|
| Collab server down | Document opens read-only via fallback UI (render last persisted snapshot when available); show banner “Collaboration unavailable” |
| DB down | Realtime sync can work temporarily; persistence fails; show degraded mode warning; retry persistence |
| Auth fails | Connection rejected with unauthorized error |
| Permission changes mid-session | On next update, server rejects; client shows banner |
