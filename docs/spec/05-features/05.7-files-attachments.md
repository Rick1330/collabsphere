# §5.7 Files & Attachments (Uploads, Storage, Linking, Security)

## §5.7.1 Overview

Files and attachments enable workspace members to upload and share assets such as PDFs, images, datasets, and diagrams. Files can be:

- stored in a workspace file library (browseable)
- attached to tasks and documents
- downloaded securely with access controls
- (P2+) previewed inline for common formats

This module must be designed for:
- secure uploads (no direct DB storage of large binaries)
- scalable object storage (S3-compatible)
- strict workspace isolation (no cross-workspace access)
- future extensibility (virus scanning, thumbnails, retention policies)

**Priority:**
- P2 (v1.1 recommended): file upload + attach + download
- P1 possible in v1 if the team can support it without impacting core features

## §5.7.3 Supported File Types & Limits (v1 defaults)

### §5.7.3.1 Allowed MIME Types (v1)
Minimum recommended allowlist:

**Documents**
- `application/pdf`
- `text/plain`
- `text/markdown`
- `application/vnd.openxmlformats-officedocument.wordprocessingml.document` (DOCX) (optional)
- `application/vnd.openxmlformats-officedocument.presentationml.presentation` (PPTX) (optional)
- `application/vnd.openxmlformats-officedocument.spreadsheetml.sheet` (XLSX) (optional)

**Images**
- `image/png`
- `image/jpeg`
- `image/webp` (optional)

**Archives (optional, risky)**
- `application/zip` (optional; if enabled, scan required)

**Code/Config (optional)**
- `application/json`
- `text/csv`

> Avoid accepting executable types (`.exe`, `.dll`, `.sh`, `.bat`) in v1.

### §5.7.3.2 Size Limits (v1 defaults)
- Max single file size: **25 MB**
- Max total workspace storage: **5 GB** (configurable)
- Max files per workspace: **10,000** (configurable)

Return explicit errors:
- `FILE_TOO_LARGE`
- `INVALID_FILE_TYPE`
- `WORKSPACE_STORAGE_LIMIT_REACHED`

## §5.7.4 Storage Architecture (Authoritative)

Files must be stored in object storage, not in PostgreSQL.

### Recommended storage choices
- Production: AWS S3 (or any S3-compatible provider)
- Local/dev: MinIO via Docker Compose

### Upload approach (recommended)
Use **pre-signed URLs** for direct-to-storage uploads:

1. Client requests upload intent (metadata) from API
2. API validates permissions, type, size
3. API returns a pre-signed PUT URL
4. Client uploads file directly to S3/MinIO
5. Client calls API to confirm upload completion
6. API marks file as `ready`

This avoids streaming files through your API servers and scales well.

## §5.7.5 File Lifecycle State Machine

States:
- `pending` (record created; upload URL issued)
- `uploaded` (client says upload complete; awaiting verification)
- `ready` (verified and available for download)
- `failed` (upload/verification failed)
- `deleted` (soft-deleted)

Transitions:
- pending → uploaded → ready
- pending → failed (timeout)
- any → deleted (soft delete)

Timeout policy:
- pending upload expires after 1 hour; cleanup job deletes orphaned pending records.

## §5.7.6 Data Model (Authoritative)

### §5.7.6.1 `files`
- `id UUID PK`
- `workspace_id UUID FK`
- `uploaded_by_user_id UUID FK`
- `status ENUM('pending','uploaded','ready','failed','deleted')`
- `original_filename VARCHAR(255)`
- `content_type VARCHAR(120)`
- `size_bytes BIGINT`
- `storage_provider ENUM('s3')`
- `storage_bucket VARCHAR(120)`
- `storage_key VARCHAR(500)` (object key/path)
- `checksum_sha256 CHAR(64)` (optional but recommended)
- `metadata JSONB` (optional: width/height for images, pages for PDFs)
- `created_at`, `updated_at`, `deleted_at`

Indexes:
- `(workspace_id, created_at DESC)`
- `(workspace_id, status)`
- `(uploaded_by_user_id, created_at DESC)`

### §5.7.6.2 Attachments (polymorphic)

Recommended: a single join table for attachments.

#### `attachments`
- `id UUID PK`
- `workspace_id UUID FK`
- `file_id UUID FK`
- `target_type ENUM('document','task','comment')` (v1: document + task; comment is optional)
- `target_id UUID`
- `created_by_user_id UUID FK`
- `created_at`
- `deleted_at NULL`

Indexes:
- `(workspace_id, target_type, target_id)`
- `(workspace_id, file_id)`

Constraints:
- target must belong to the same workspace as the file (enforced in service logic)
- prevent attaching `status != ready` files

## §5.7.9 API Contracts (Authoritative)

Base: `/api/v1/workspaces/:workspaceId/files`

### 1) Create Upload Intent (Get pre-signed URL)
`POST /api/v1/workspaces/:workspaceId/files/upload-intent`

Request:
```json
{
  "originalFilename": "diagram.png",
  "contentType": "image/png",
  "sizeBytes": 523112,
  "checksumSha256": "optional-sha256-hex"
}
```

Response (201):
```json
{
  "data": {
    "file": {
      "id": "file-uuid",
      "status": "pending",
      "originalFilename": "diagram.png",
      "contentType": "image/png",
      "sizeBytes": 523112
    },
    "upload": {
      "method": "PUT",
      "url": "https://storage...presigned-url...",
      "headers": {
        "Content-Type": "image/png"
      },
      "expiresAt": "2025-07-17T13:00:00Z"
    }
  }
}
```

Errors:
- `403 FORBIDDEN` (Viewer)
- `400 INVALID_FILE_TYPE`
- `400 FILE_TOO_LARGE`
- `400 WORKSPACE_STORAGE_LIMIT_REACHED`
- `404 WORKSPACE_NOT_FOUND`

---

### 2) Confirm Upload Completion
`POST /api/v1/workspaces/:workspaceId/files/:fileId/complete`

Request:
```json
{
  "checksumSha256": "optional-sha256-hex"
}
```

Response (200):
```json
{
  "data": {
    "file": {
      "id": "file-uuid",
      "status": "ready",
      "downloadUrl": "https://api.../download?token=..."
    }
  }
}
```

Notes:
- API may verify object exists and matches size/checksum before marking `ready`.

Errors:
- `400 UPLOAD_NOT_FOUND_IN_STORAGE`
- `400 CHECKSUM_MISMATCH`
- `403 FORBIDDEN`
- `404 FILE_NOT_FOUND`

---

### 3) List Files
`GET /api/v1/workspaces/:workspaceId/files`

Query:
- `page`, `pageSize`
- `type=image/png,application/pdf` (optional)
- `uploadedBy=uuid` (optional)
- `search=diagram` (optional)

Response (200):
```json
{
  "data": {
    "items": [
      {
        "id": "file-uuid",
        "originalFilename": "diagram.png",
        "contentType": "image/png",
        "sizeBytes": 523112,
        "status": "ready",
        "uploadedBy": { "id": "u1", "fullName": "Jane Doe" },
        "createdAt": "2025-07-17T12:00:00Z"
      }
    ]
  },
  "meta": {
    "pagination": { "page": 1, "pageSize": 25, "totalItems": 120, "totalPages": 5 }
  }
}
```

---

### 4) Download File (Signed URL or Proxy)
Two valid approaches:

#### Option A (recommended): Signed GET URL
`GET /api/v1/workspaces/:workspaceId/files/:fileId/download`

Response (200):
```json
{
  "data": {
    "downloadUrl": "https://storage...presigned-get-url...",
    "expiresAt": "2025-07-17T12:05:00Z"
  }
}
```

#### Option B: API proxies file stream (not recommended at scale)
`GET /api/v1/workspaces/:workspaceId/files/:fileId/stream`

> v1.1 can implement Option A only.

Errors:
- `403 FORBIDDEN`
- `404 FILE_NOT_FOUND`
- `400 FILE_NOT_READY`

---

### 5) Delete File (Soft Delete)
`DELETE /api/v1/workspaces/:workspaceId/files/:fileId`

Role:
- Manager+ for any file
- Member for own uploaded files

Response:
```json
{ "data": { "message": "File deleted." } }
```

Side effects:
- Remove/soft-delete attachments referencing it (policy: keep attachments but mark broken; recommended: soft-delete attachments too)

---

### 6) Attach File to Task/Document
`POST /api/v1/workspaces/:workspaceId/attachments`

Request:
```json
{
  "fileId": "file-uuid",
  "targetType": "task",
  "targetId": "task-uuid"
}
```

Response (201):
```json
{
  "data": {
    "attachment": {
      "id": "att-uuid",
      "fileId": "file-uuid",
      "targetType": "task",
      "targetId": "task-uuid",
      "createdAt": "2025-07-17T12:10:00Z"
    }
  }
}
```

Errors:
- `400 FILE_NOT_READY`
- `404 FILE_NOT_FOUND`
- `404 TARGET_NOT_FOUND`
- `403 FORBIDDEN`
- `400 WORKSPACE_MISMATCH`
- `409 ATTACHMENT_EXISTS`

---

### 7) List Attachments for a Target
`GET /api/v1/workspaces/:workspaceId/attachments?targetType=task&targetId=task-uuid`

## §5.7.10 Security Requirements

### Upload security
- Strict MIME allowlist validation on upload intent
- Enforce size limits server-side
- Ensure pre-signed URL expires quickly (5–15 minutes)
- Ensure storage key is unguessable and scoped:
  - `workspaces/<workspaceId>/files/<fileId>/<sanitizedFilename>`
- Never allow client to choose bucket or storage key directly

### Download security
- Must validate:
  - user is workspace member
  - file belongs to workspace
  - file is `ready` and not deleted
- Use pre-signed GET URLs with very short TTL (1–5 minutes)

### Malware scanning (v2 or optional)
- v1.1 optional: integrate a scanning service or run ClamAV in a worker
- Until scanning exists, avoid accepting risky file types (e.g., zip)

### XSS / content sniffing
- Always set download headers:
  - `Content-Disposition: attachment; filename="..."`
  - `X-Content-Type-Options: nosniff`
- If previewing images/PDFs inline (P2), use safe iframe/embed constraints.

## §5.7.11 Events

| Event | Trigger | Payload |
|------|---------|---------|
| `file.upload_intent_created` | upload intent | `{ workspaceId, fileId, userId }` |
| `file.upload_completed` | complete endpoint | `{ workspaceId, fileId, userId, sizeBytes }` |
| `file.deleted` | delete | `{ workspaceId, fileId, actorId }` |
| `attachment.created` | attach | `{ workspaceId, attachmentId, fileId, targetType, targetId }` |
| `attachment.deleted` | detach | `{ workspaceId, attachmentId }` |

Notifications (optional):
- Do not notify on every file upload (noise).
- Notify only if attached to a task and task participants have “task updates” enabled (P2).

## §5.7.12 Edge Cases (Must Be Handled)

| Scenario | Expected Behavior |
|---------|-------------------|
| User requests upload intent but never uploads | Record remains pending; cleanup job removes after 1 hour and deletes object if exists. |
| Client uploads but never calls complete | Storage object exists; file remains pending; cleanup job reconciles or deletes. |
| Upload intent reused with different file | Reject complete if checksum/size mismatch. |
| Two completes called concurrently | Idempotent: first marks ready, second returns ready. |
| File deleted while attached to tasks/docs | UI shows attachment as missing; recommended: cascade soft-delete attachments. |
| Workspace archived | Disallow new upload intents and attach operations; allow downloads. |
| Viewer tries upload/attach | UI hides; API returns 403. |
| Storage provider outage | Upload intent fails (503) OR complete fails; UI shows retry. |
