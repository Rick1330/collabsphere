# §5.3 Templates (Workspace Templates & Document Templates)

## §5.3.1 Overview

Templates are a first-class feature in CollabSphere. They accelerate onboarding and enforce consistent structure by generating:

- Workspace structure (folders, starter documents, task board columns, settings)
- Individual documents with pre-filled outlines (PRD, SRS, Thesis, Meeting Notes, etc.)

Templates must support both:
- **Professional workflows** (software teams)
- **Academic workflows** (student projects + supervision)

**Priority:** P0 for built-in templates + application flow (v1)  
**Priority:** P2/P3 for custom template creation and sharing (v1.1/v2)

---

## §5.3.2 Template Types

### §5.3.2.1 Workspace Templates (P0)

A workspace template generates an entire workspace blueprint:
- default folder hierarchy
- starter documents
- task board columns
- workspace settings defaults (feature flags)
- role label mapping (cosmetic)

Examples:
- Professional: “Software Development Project”
- Academic: “Senior Project”
- General: “Blank Workspace”

### §5.3.2.2 Document Templates (P0)

A document template generates a single document with:
- pre-filled headings and placeholder text
- optional metadata (recommended formatting, export defaults)

Examples:
- Professional: PRD, RFC, ADR, Sprint Retro
- Academic: RAD, SRS, Thesis Outline, Proposal, Meeting Minutes

### §5.3.2.3 Task Board Templates (P1)

Task boards can vary by workflow (Kanban vs Sprint vs Academic milestones). In v1, task board columns are provisioned through the workspace template. In v1.1+, task board templates can be applied independently.

---

## §5.3.3 Template Scope & Ownership

Templates exist in one of these scopes:

| Scope | Description | Who Can Create/Edit |
|-------|-------------|---------------------|
| `system` | Built-in templates shipped with the platform | Platform Admin / maintainers (via code or admin tooling) |
| `workspace` | Templates custom to a workspace | Workspace Owner/Admin (v1.1+) |
| `organization` | Shared templates across a group of workspaces | v2+ |
| `public` | Community template marketplace | v2+ |

**v1 scope:** `system` only (built-in templates)  
**v1.1:** enable `workspace` custom templates (create from document)  
**v2+:** organization + public marketplace

## §5.3.4 Template Format (Authoritative)

Templates are stored as structured JSON to support robust application and preview.

### §5.3.4.1 Workspace Template Schema (v1)

```json
{
  "id": "tpl_workspace_professional_software_project_v1",
  "kind": "workspace",
  "category": "professional",
  "name": "Software Development Project",
  "description": "A workspace structure for product development teams.",
  "version": 1,
  "schemaVersion": 1,
  "defaults": {
    "workspaceSettings": {
      "submissionWorkflowEnabled": false,
      "allowViewerCommentsOnDocs": true,
      "allowViewerCommentsOnTasks": false
    },
    "roleLabels": {
      "OWNER": "Owner",
      "ADMIN": "Admin",
      "MANAGER": "Tech Lead",
      "MEMBER": "Developer",
      "VIEWER": "Stakeholder"
    }
  },
  "structure": {
    "folders": [
      { "key": "product", "name": "Product", "parentKey": null },
      { "key": "architecture", "name": "Architecture", "parentKey": null }
    ],
    "documents": [
      {
        "key": "prd",
        "title": "Product Requirements",
        "folderKey": "product",
        "documentTemplateId": "tpl_doc_professional_prd_v1"
      }
    ],
    "taskBoard": {
      "columns": [
        { "key": "backlog", "name": "Backlog", "status": "backlog", "position": 1 },
        { "key": "todo", "name": "To Do", "status": "todo", "position": 2 },
        { "key": "in_progress", "name": "In Progress", "status": "in_progress", "position": 3 },
        { "key": "review", "name": "Review", "status": "in_review", "position": 4 },
        { "key": "done", "name": "Done", "status": "done", "position": 5 }
      ]
    }
  }
}
```

Notes:
- `key` fields provide deterministic references during application.
- `position` is used for ordering columns.
- Workspace template references document templates by `documentTemplateId`.

### §5.3.4.2 Document Template Schema (v1)

Document templates define initial editor content.

Content format options:
- **Preferred:** Tiptap JSON document (ProseMirror-compatible)
- **Fallback:** Markdown converted to Tiptap JSON at creation time

**v1 recommended approach:** store **Markdown** in templates, convert to Tiptap JSON server-side for initial CRDT state seeding. This keeps templates human-editable and source-control friendly.

Example (Markdown-based template record):
```json
{
  "id": "tpl_doc_academic_srs_v1",
  "kind": "document",
  "category": "academic",
  "name": "Software Requirements Specification (SRS)",
  "description": "A structured SRS outline suitable for academic projects.",
  "version": 1,
  "schemaVersion": 1,
  "contentFormat": "markdown",
  "content": "# Software Requirements Specification\n\n## 1. Introduction\n\n## 2. Overall Description\n\n## 3. System Features\n\n## 4. External Interface Requirements\n\n## 5. Non-Functional Requirements\n\n## 6. Appendices\n"
}
```

Conversion rules:
- Markdown is parsed and converted into a Tiptap/ProseMirror doc
- That doc seeds a new Yjs document state (`content_yjs`) on document creation
- Store derived plaintext in `documents.content_plaintext` for search indexing

## §5.3.6 Template Browsing & Preview (UI/UX)

  - name

### §5.3.6.2 Templates Page (P1)

Route: `/w/:workspaceId/templates`

- Browse built-in templates available to this workspace type

- (v1.1+) Manage workspace custom templates

Features (v1):

- Preview modal
- “Use template” button:
  - Workspace templates can only be used during workspace creation in v1
  - Document templates can be used any time to create documents

## §5.3.7 Template Application Engine (Backend)

Template application must be safe, transactional, idempotent, and auditable.

### §5.3.7.1 Workspace Template Application (P0)

Applied only during workspace creation in v1.

Atomic steps (must be in a DB transaction):
1. Create workspace row
2. Create owner membership row
3. Apply workspace settings defaults
4. Create folders
5. Create documents (and seed CRDT state)
6. Create task board columns
7. Record activity: `workspace.created` and `workspace.template_applied`

Failure handling:
- If any step fails, rollback everything
- Return error `TEMPLATE_APPLICATION_FAILED`

Idempotency:
- Support `X-Idempotency-Key` on workspace creation endpoint
- If repeated with same key, return original created workspace

### §5.3.7.2 Document Template Application (P0)

Applied on document creation when `templateId` is provided:
1. Load template
2. Convert template content (Markdown → Tiptap JSON)
3. Seed Yjs document state
4. Persist `documents.content_yjs` + derived plaintext

## §5.3.9 API Contracts (Authoritative)

### §5.3.9.1 List Templates
`GET /api/v1/templates`

Query params:
- `kind=workspace|document`
- `category=professional|academic|general`
- `scope=system` (v1 only)
- `search=...` (optional)

Response:
```json
{
  "data": {
    "items": [
      {
        "id": "tpl_doc_professional_prd_v1",
        "kind": "document",
        "category": "professional",
        "scope": "system",
        "name": "Product Requirements Document (PRD)",
        "description": "A PRD outline for product teams.",
        "version": 1
      }
    ]
  }
}
```

---

### §5.3.9.2 Get Template (for preview)
`GET /api/v1/templates/:templateId`

Response:
```json
{
  "data": {
    "template": {
      "id": "tpl_workspace_academic_senior_project_v1",
      "kind": "workspace",
      "category": "academic",
      "name": "Senior Project",
      "description": "Academic workspace with submission workflow enabled.",
      "version": 1,
      "structurePreview": {
        "folderCount": 6,
        "documentCount": 10,
        "taskColumns": ["Backlog", "To Do", "In Progress", "Review", "Done"],
        "settings": {
          "submissionWorkflowEnabled": true
        }
      }
    }
  }
}
```

Notes:
- For preview, do not return huge content unless requested.
- If document template content is large, use `?includeContent=true` gated by role.

---

### §5.3.9.3 Create Document from Template
This is handled by the documents create endpoint:

`POST /api/v1/workspaces/:workspaceId/documents`

Request includes:
```json
{
  "title": "SRS",
  "folderId": "uuid-or-null",
  "templateId": "tpl_doc_academic_srs_v1"
}
```

## §5.3.10 Data Model (Authoritative)

### `templates` (system templates stored in DB)
- `id VARCHAR PK` (stable identifier)
- `kind ENUM('workspace','document')`
- `category ENUM('professional','academic','general')`
- `scope ENUM('system','workspace','organization','public')` (v1 uses system)
- `name VARCHAR(120)`
- `description VARCHAR(280)`
- `version INT`
- `schema_version INT`
- `content_format ENUM('json','markdown')` (document templates)
- `content JSONB` (template body; for workspace templates store structure JSON; for documents store markdown or JSON)
- `is_enabled BOOLEAN DEFAULT true`
- `created_at`, `updated_at`

Indexes:
- `(kind, category, scope)`
- text search index on `(name, description)` (optional)

### Why store system templates in DB (vs code)?
- Allows preview and listing without redeploy
- Allows future admin UI to manage templates
- Allows easy export/import of templates later

Alternative: store templates in code and seed DB on startup/migration. Both acceptable; if you seed DB, document the seeding mechanism.

## §5.3.12 Edge Cases

| Scenario | Expected Behavior |
|---------|-------------------|
| Template disabled | API returns `404 TEMPLATE_NOT_FOUND` or `403 TEMPLATE_DISABLED` depending on policy; UI hides it. |
| Template references missing document template | Workspace creation fails transactionally with `TEMPLATE_INVALID`. |
| Template schema version mismatch | Reject with `TEMPLATE_SCHEMA_UNSUPPORTED` until migrated. |
| Document template contains unsupported formatting | Convert best-effort; strip unsupported nodes; log warning `template_content_sanitized`. |
| User tries to use academic workspace template in professional workspace type | Backend rejects: `400 TEMPLATE_CATEGORY_MISMATCH`. |
| Large template content | Do not return full content by default in preview API. |
| Concurrent workspace creation using same idempotency key | Return same workspace result. |
