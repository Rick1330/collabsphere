# §5.9 Admin Console (Platform Administration)

## §5.9.1 Overview

The Admin Console provides platform-level control for **Platform Admins** to operate CollabSphere safely. It includes:

- Admin dashboard (platform health + usage overview)
- User management (search, deactivate/reactivate, admin notes)
- Workspace management (view, archive, force-delete, ownership inspection)
- Audit log access (security and sensitive actions)
- System settings (limited in v1; expands in v2)

**Priority:** P1 (not required for basic collaboration, but required for real operation and security oversight)

---

## §5.9.2 Personas & Permissions

### Primary Persona
- **Platform Admin** (global role `ADMIN`)

### Access Rules
- All `/admin/*` routes require:
  - authentication (JWT)
  - global role `ADMIN`
- Non-admin users:
  - must receive `403 FORBIDDEN`
  - UI must hide all admin entry points (except if deep-linked, show 403 page)

---

- `/admin/settings` — System settings (minimal v1)

### Admin Sidebar
(Defined in §3.3.5)

### Global “Back to App” Link
- Always present at top of admin sidebar
- Navigates to `/dashboard`

## §5.9.4 Admin Dashboard (v1)

### Purpose
Provide a high-level snapshot of platform usage and operational health.

### Dashboard Widgets (v1 minimum)

| Widget | Description | Data Source |
|--------|-------------|------------|
| Total users | Count of active users | `users` |
| New users (7d) | New registrations last 7 days | `users.created_at` |
| Total workspaces | Count of active workspaces | `workspaces` |
| Active workspaces (7d) | Workspaces with activity in last 7 days | `activity_events` |
| Storage usage | Total file storage used (if files enabled) | `files.size_bytes` |
| Error rate (optional) | API 5xx count last 24h | observability tooling (later) |
| Queue depth (optional) | Email/export jobs queued | BullMQ |

### UI Requirements
- Loading skeletons
- “Last updated” timestamp
- Manual refresh button
- Links from widgets to the relevant admin pages (Users/Workspaces/Audit)

## §5.9.5 User Management

### §5.9.5.1 User List Page (`/admin/users`)

Features:
- Search by:
  - email (exact/partial)
  - full name
  - userId (exact)
- Filters:
  - status: active / deactivated / unverified / deleted
  - auth provider: local / google
  - global role: USER / ADMIN
- Columns:
  - name
  - email
  - status badge
  - global role badge
  - auth provider badge
  - createdAt
  - lastLoginAt (P2 if tracked)
- Row actions:
  - View details
  - Deactivate / Reactivate
  - Reset password (local auth only; optional v1)
  - Promote/Demote admin (v1 optional; if included, require confirmation)

Pagination:
- 50/page default
- server-side pagination required

### §5.9.5.2 User Detail Page (`/admin/users/:userId`)

Displays:
- Profile:
  - name, email, avatar
  - auth provider
  - verification status
  - account status
  - createdAt, updatedAt
  - lastLoginAt (if tracked)
- Workspace memberships (read-only list):
  - workspace name
  - workspace type
  - role in workspace
  - join date
- Admin actions:
  - deactivate/reactivate
  - reset password (local only; optional)
  - revoke sessions (logout-all)
  - add admin note (P2)

---

### §5.9.5.3 Deactivate / Reactivate User (Authoritative Behavior)

When a user is deactivated:
- `users.is_active = false`
- All refresh tokens revoked (force logout)
- Access token expires naturally (15 minutes)
- User cannot login or refresh

When reactivated:
- `users.is_active = true`
- User can login again normally

Route: `/admin/settings`

v1 contents (minimal):
- Read-only environment info:
  - API version
  - build commit hash
  - uptime (optional)

## §5.9.8 Security Requirements (Admin Console)

### §5.9.8.1 Admin Access Logging
Every admin action must write an audit log entry (see §5.8.5), including:
- actionKey
- actorId
- ip address
- userAgent
- target type/id

### §5.9.8.2 Confirmation for Dangerous Actions
The following actions require typed confirmation:

| Action | Confirmation |
|--------|-------------|
| Force delete workspace | Type workspace name to confirm |
| Promote user to admin | Type “PROMOTE” |
| Deactivate user | Confirm modal |
| Reset password | Confirm modal |

### §5.9.8.3 Principle of Least Privilege
- Admin console endpoints are isolated under `/api/v1/admin/*`
- Admin console UI is isolated under `/admin/*`
- Use separate guards:
  - `JwtAuthGuard`
  - `GlobalRolesGuard` requiring `ADMIN`

## §5.9.10 Data Model Implications

No new tables are required beyond:
- `users`
- `workspaces`
- `workspace_members`
- `refresh_tokens`
- `audit_log`
- (optional) `admin_notes` (P2)

Optional P2 table:
### `admin_notes`
- `id UUID`
- `target_type ENUM('user','workspace')`
- `target_id UUID`
- `note TEXT`
- `created_by_admin_id UUID`
- `created_at`

## §5.9.11 Events Emitted

| Event | Trigger | Payload |
|------|---------|---------|
| `admin.user_deactivated` | deactivate | `{ adminId, userId }` |
| `admin.user_reactivated` | reactivate | `{ adminId, userId }` |
| `admin.user_sessions_revoked` | revoke sessions | `{ adminId, userId, revokedCount }` |
| `admin.workspace_archived` | archive override | `{ adminId, workspaceId }` |
| `admin.workspace_unarchived` | unarchive override | `{ adminId, workspaceId }` |
| `admin.workspace_force_deleted` | force delete | `{ adminId, workspaceId }` |

All must also create audit log entries.

## §5.9.12 Edge Cases (Must Be Handled)

| Scenario | Expected Behavior |
|---------|-------------------|
| Admin deactivates themselves | Allowed only if there is another admin remaining (recommended safeguard). Otherwise block. |
| Admin force deletes a workspace they are not a member of | Allowed (admin context). Must not require workspace membership checks. |
| Deactivated user still has active access token | Access token remains valid until expiry (15m). Refresh blocked immediately. |
| OAuth-only user password reset by admin | Either block with `400 OAUTH_USER_NO_PASSWORD` or support setting a local password with explicit “convert to local” action (v2). |
| Large user base | Admin endpoints must be indexed and paginated; no full-table scans. |
| Audit log grows large | Partitioning (P2) + retention policy enforced. |

Metrics:
