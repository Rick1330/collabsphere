# §5.4 Documents (Hierarchy, Editor, Collaboration, Versioning, Locking, Export)

## §5.4.1 Overview

The Documents capability provides a structured, collaborative documentation system inside each workspace. It includes:

- Hierarchical organization (folders + nested documents)
- Real-time collaborative editing (Tiptap + Yjs + Hocuspocus)
- Comments (inline/general) and mentions (see §4.8)
- Document lifecycle controls:
  - Locking/unlocking (prevent edits)
  - Academic submission/review statuses (see §4.11)
- Version history + restore
- Export (PDF + Markdown)

**Priority:** P0 (documents + realtime editing + hierarchy)  
**Priority:** P1 (version history + export)  
**Priority:** P2 (outline panel, slash commands, attachments)

## §5.4.4 Document Hierarchy Model (Folders + Documents)

CollabSphere supports a nested hierarchy:

- **Folder**: a container node
- **Document**: a leaf node (editable content)

### Rules (v1)
- Folders can be nested up to **10 levels**
- A document belongs either:
  - to a folder, or
  - to the workspace root
- Titles must be unique **within the same folder** (recommended, not strictly required)
- Drag-and-drop reorder is supported:
  - reorder within a folder
  - move document into another folder
  - move folder into another folder (but prevent cycles)

### Ordering Strategy
Use fractional ordering:
- Each node has `position` (decimal)
- When inserting between items, assign midpoint (e.g., 1.0, 2.0 → insert 1.5)
- Periodic “rebalance” job can normalize positions (P3)

## §5.4.5 Document Editor Capabilities (v1)

### Required formatting (P0/P1)
- Paragraphs
- Headings H1–H6
- Bold, italic, underline, strikethrough
- Bullet list, ordered list
- Blockquote
- Inline code + code block
- Links
- Undo/redo (local)
- Paste handling (sanitize)

### Optional (P1/P2)
- Tables (P1 if feasible)
- Images (P2, depends on file uploads)
- Slash commands (P2)
- Outline / Table of contents panel (P2)

### Content safety
- Store content as **structured ProseMirror/Tiptap doc** and/or Yjs state
- Sanitize any HTML paste on the client and server
- Never store raw HTML as the canonical source

## §5.4.6 Real-Time Collaboration (Authoritative)

### Stack
- Tiptap editor + y-prosemirror binding
- Yjs CRDT doc per document
- Hocuspocus server providing:
  - sync
  - awareness (presence/cursors)
  - persistence hooks

### Collaboration rules
- Update broadcast target: all clients in `doc:<documentId>` room
- Latency target: <500ms under normal conditions
- Offline tolerance: allow local edits; sync on reconnect
- Permission enforcement must exist server-side:
  - Viewer can connect but cannot publish updates
  - Locked/submitted/approved docs are read-only for Members

> REST APIs return metadata; **document content is loaded via collaboration server**.

## §5.4.7 Document Lifecycle & Status

### Standard document statuses (always available)
- `draft`
- `archived`

### Academic workflow statuses (when academic mode enabled)
- `submitted`
- `changes_requested`
- `approved`

### Edit permission logic (effective)
Document is editable if and only if:
- workspace is not archived AND
- document is not deleted AND
- document is not locked (unless editor is lock owner or Admin/Owner) AND
- status is not `submitted` or `approved` for Members

## §5.4.8 Document Locking (P1)

Locking exists to prevent edits during critical formatting or review phases (especially academic).

### Behavior
- Lock is toggled by Manager+ (Owner/Admin/Manager)
- When locked:
  - Only the lock owner or Admin/Owner can edit
  - All Members see read-only banner: “Locked by Jane”
- Lock metadata stored:
  - `locked_by_user_id`
  - `locked_at`

### UI
- Lock icon in editor header
- Tooltip: “Lock document to prevent edits”
- When locked:
  - red/amber banner at top
  - lock status visible in document list

## §5.4.9 Version History & Restore (P1)

### Why versioning exists
- Safety net for accidental deletion/overwrite
- Enables “restore to earlier state”
- Required for academic “submission snapshot” records (§4.11)

### Versioning approach (v1)
Create a version snapshot when:
1. Manual snapshot action (button: “Save version”) (P1)
2. Document submission (academic) (P0 for academic workflow)
3. Periodic snapshot:
   - every 10 minutes while document is being edited OR
   - on editor disconnect event (best effort)

**Do not create versions per keystroke.** This must be time-based or event-based.

### Stored per version
- `document_id`
- `version_number` (incrementing)
- `created_by_user_id` (who triggered snapshot; “system” for auto)
- `created_at`
- `yjs_state` (BYTEA snapshot)
- `plaintext` (optional, for diff and search)
- `reason` enum:
  - `manual`
  - `auto`
  - `submitted`
  - `approved`
  - `before_restore`

### Restore rules
- Restore is Manager+ (Owner/Admin/Manager)
- Restore action:
  - creates a “before_restore” snapshot first
  - replaces current `documents.content_yjs` with snapshot state
  - updates `updated_at`
  - emits events + activity

### Diff viewing (v1 scope)
- v1 can implement **basic diff** on plaintext only (optional)
- Rich structured diff is complex; v1.1+ improvement

## §5.4.10 Export (PDF + Markdown) (P1)

### Export types (v1)
- Single document export:
  - PDF
  - Markdown
- Workspace export:
  - v1.1+ (zip of docs), unless you explicitly want v1

### Export rules
- Export respects permissions:
  - Viewer can export only if workspace setting allows (`allowViewerExport=true`)
- Exports must preserve:
  - headings
  - lists
  - code blocks
  - links
  - tables (if supported)

### Implementation (recommended)
- Markdown export:
  - server converts ProseMirror/Tiptap doc → Markdown
- PDF export:
  - server renders HTML then prints to PDF using Playwright/Chromium OR a PDF renderer
- Export should run in a background job for large docs:
  - enqueue job in BullMQ
  - notify user when ready
  - provide download link with short-lived signed URL (P2 for file storage)

## §5.4.12 API Contracts (Authoritative)

Base: `/api/v1/workspaces/:workspaceId`

### 1) List Document Tree
`GET /api/v1/workspaces/:workspaceId/documents/tree`

Response (200):
```json
{
  "data": {
    "tree": [
      {
        "type": "folder",
        "id": "folder-uuid",
        "name": "Chapter 1",
        "parentId": null,
        "position": 1.0,
        "children": [
          {
            "type": "document",
            "id": "doc-uuid",
            "title": "Introduction",
            "status": "draft",
            "isLocked": false,
            "parentFolderId": "folder-uuid",
            "position": 1.0,
            "updatedAt": "2025-07-17T12:10:00Z"
          }
        ]
      }
    ]
  }
}
```

Errors:
- `403 NOT_WORKSPACE_MEMBER`
- `404 WORKSPACE_NOT_FOUND`

### 8) Delete Document
`DELETE /api/v1/workspaces/:workspaceId/documents/:documentId`

Rules:
- Soft delete (set `deleted_at`); remove from active listings.
- Disallow deletion when status is `submitted` or `approved` (return `400 DOCUMENT_READONLY_STATUS`).
- Permissions: Owner/Admin/Manager can delete; Member can delete own docs only; Viewer cannot delete.

Errors:
- `403 FORBIDDEN`
- `400 WORKSPACE_ARCHIVED_READONLY`
- `400 DOCUMENT_READONLY_STATUS`
- `404 DOCUMENT_NOT_FOUND`

## §5.4.13 Data Model (Authoritative)

### `folders`
- `id UUID PK`
- `workspace_id UUID FK`
- `name VARCHAR(120)`
- `parent_id UUID NULL` (self FK)
- `position DECIMAL NOT NULL`
- `created_by UUID FK`
- `created_at`, `updated_at`, `deleted_at`

Indexes:
- `(workspace_id, parent_id, position)`
Constraints:
- prevent cycles via application logic (and optional DB constraints)

### `documents`
- `id UUID PK`
- `workspace_id UUID FK`
- `folder_id UUID NULL`
- `title VARCHAR(200)`
- `status ENUM('draft','submitted','changes_requested','approved','archived')`
- `is_locked BOOLEAN DEFAULT false`
- `locked_by_user_id UUID NULL`
- `locked_at TIMESTAMPTZ NULL`
- `content_yjs BYTEA` (canonical)
- `content_plaintext TEXT` (derived for search)
- `search_vector TSVECTOR` (generated/maintained)
- `created_by UUID FK`
- `updated_by UUID FK NULL`
- `created_at`, `updated_at`, `deleted_at`
- `position DECIMAL NOT NULL`

Indexes:
- `(workspace_id, folder_id, position)`
- `(workspace_id, updated_at DESC)`
- GIN `(search_vector)`

### `document_versions`
- `id UUID PK`
- `document_id UUID FK`
- `workspace_id UUID FK` (denormalized for filtering)
- `version_number INT`
- `reason ENUM('manual','auto','submitted','approved','before_restore')`
- `yjs_state BYTEA`
- `plaintext TEXT NULL`
- `created_by UUID NULL` (null for system)
- `created_at`

Indexes:
- `(document_id, version_number DESC)`
- `(workspace_id, created_at DESC)`

## §5.4.15 Edge Cases (Must Be Handled)

| Scenario | Expected Behavior |
|---------|-------------------|
| User opens doc they can view but not edit | Read-only editor; collaboration presence visible; updates rejected server-side. |
| Document locked while user is editing | Client receives realtime metadata update; switches to read-only; shows banner. |
| Role downgraded mid-session | Hocuspocus rejects writes; UI shows “Edit access removed.” |
| Folder moved into its own child | Reject with `400 INVALID_PARENT` (cycle prevention). |
| Delete folder not empty | Reject with `400 FOLDER_NOT_EMPTY` (v1). |
| Restore version while others are editing | Broadcast `document:restored` event; clients reload state (or show banner “Document restored to version X”). |
| Export requested repeatedly | Deduplicate by idempotency key OR queue multiple jobs; recommend dedupe within 60s. |
| Very large doc export | Async job required; show progress in UI; notify when ready. |

## §5.4.16 Testing Requirements

### Unit
- hierarchy move validation (cycle prevention)
- lock/unlock permission checks
- version snapshot creation rules
- export format validation

### Integration
- create doc seeds CRDT state + plaintext
- tree endpoint returns correct nested structure
- lock prevents edits by non-lock-owners; Admin/Owner may override (server-side)
- restore creates before_restore snapshot and updates content

### E2E (Playwright)
- create folder + document + reorder via drag/drop
- open doc in two browsers → realtime editing works
- lock doc from one user → other becomes read-only
- create version → restore version → content changes visibly
- export to PDF/Markdown → download works
