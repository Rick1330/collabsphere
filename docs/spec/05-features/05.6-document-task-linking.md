# §5.6 Document ↔ Task Linking (Create Task from Document Selection, Deep Links, Anchors)

## §5.6.1 Overview

Document ↔ Task Linking connects planning (tasks) with execution context (documents). It allows users to:

- Highlight text in a document and **create a task from that selection**
- Keep a durable link from the task back to the **exact document context**
- Open the task and jump back to the relevant section of the document instantly

This feature is a major differentiator: tasks are not isolated cards; they are connected to the knowledge they represent.

**Priority:**
- P1: Create task from document selection + deep link back to document
- P2: Multiple links per task, drag-to-link, backlink badges in doc
- P3: Dependency graphs between documents and tasks

---

## §5.6.2 Key Concepts

### §5.6.2.1 “Link” vs “Anchor”
- A **Link** is a relationship record between a Task and a Document.
- An **Anchor** is the best-effort pointer to the place in the document where the task was created.

Because documents are collaboratively edited in real-time (CRDT/Yjs), absolute positions can change. Anchors must degrade gracefully.

### §5.6.2.2 Anchor Reliability Principle
Anchors are **best-effort**, not perfect. CollabSphere must:
- attempt to locate and highlight the originally selected text
- if it can’t, still open the document and show the link metadata (“Original text moved or changed”)

---

## §5.6.3 Permissions

To create a task from a document selection, the user must:
- be a workspace member with **Member+** role (task creation permission)
- have permission to **view** the document (Viewer+)
- if the document is locked/submitted/approved, task creation is still allowed (it does not modify doc content), but selection must be possible in read-only mode

To view and use a link:
- any user who can view the task and document can click the link
- link visibility must never leak cross-workspace data

---

## §5.6.4 User Stories Served (Representative)

- As a **Member**, I want to highlight a paragraph and create a task so that work items stay tied to the documentation context.
- As a **Manager**, I want tasks to link back to specific document sections so that reviews and planning are traceable.
- As a **Supervisor**, I want to see which document sections are blocked by tasks so I can guide students effectively. (P2/P3)

## §5.6.5 UI/UX — Create Task from Document Selection (P1)

### Entry Point
Inside the Document Editor (`/w/:wId/documents/:docId`):

1. User selects text (highlight)
2. A floating selection menu appears with actions:
   - **Comment** (existing)
   - **Create task** (this feature)
3. User clicks **Create task**

### Create Task Modal (pre-filled)
The modal opens with:

- **Title** (required)
  - Default: derived from selection, truncated to 80 chars
  - Example: “Expand on security constraints”
- **Description** (optional)
  - Pre-filled with the selected quote (blockquote style), plus a link reference
- **Link Preview** (read-only)
  - “Linked to: Document Title → selected text excerpt”
- Normal fields:
  - Assignee, due date, priority, labels

Buttons:
- Cancel
- Create Task

### After Create
- Task is created and appears in board/list
- Toast: “Task created and linked to document”
- Optional (P2): a small inline badge appears near selected text: “✅ Linked task: [task title]”

## §5.6.6 UI/UX — Task Detail: Jump Back to Document (P1)

In Task Detail Panel:

Add a “Linked Resources” section:

```
Linked Resources
- 📄 Requirements Doc — “The system must encrypt…”
  [Open] [Copy link]
```

Behavior:
- Clicking **Open** navigates to:
  - `/w/:wId/documents/:docId?link=<linkId>`
- Document editor:
  - attempts to scroll to anchor location
  - highlights the matched text briefly (3–5 seconds)
  - shows small banner: “Jumped to linked section from task”

If anchor cannot be resolved:
- still opens the document
- shows banner: “Original linked text changed or moved. Showing document at last known context.”

## §5.6.7 Anchor Data Model (P1)

Anchors must store enough information to re-locate content later even after edits.

### Anchor Structure (stored as JSONB)
```json
{
  "type": "textQuote",
  "quote": "Passwords must be hashed using bcrypt or Argon2...",
  "quoteHash": "sha256-of-quote",
  "createdFrom": 120,
  "createdTo": 176,
  "createdAtVersionHint": 12,
  "headingPath": ["3", "3.2", "Security Requirements"]
}
```

**Field meanings:**
- `quote`: the selected text (truncate to max 280 chars)
- `quoteHash`: allows fast matching and integrity checks
- `createdFrom/createdTo`: numeric positions at creation time (best-effort)
- `createdAtVersionHint`: optional “document version number” or internal revision for heuristics
- `headingPath`: optional heading breadcrumb derived from document outline at time of selection (helps fallback navigation)

### Anchor Resolution Algorithm (Frontend)
When opening `/documents/:docId?link=<linkId>`:

1. Fetch link record (includes anchor)
2. Try to find `quote` within current derived plaintext:
   - exact match first
   - then normalized whitespace match
3. If match found:
   - scroll editor to match range
   - highlight range
4. Else:
   - if headingPath exists, scroll to closest heading
   - else scroll to top
   - show “anchor unresolved” banner

> Note: This is intentionally best-effort and avoids deep CRDT position tracking complexity.

## §5.6.8 Backend Design (P1)

### Creation flow
When user creates a task from a document selection:
- backend creates the task
- backend creates a link record with:
  - workspaceId (must match)
  - taskId
  - documentId
  - anchor JSON
  - createdBy

### Reading flow
- task detail endpoint returns linked resources summary
- document editor route uses query param to fetch link and anchor data

## §5.6.9 API Contracts (Authoritative)

### §5.6.9.1 Create Task (with optional source link)
`POST /api/v1/workspaces/:workspaceId/tasks`

Request (extended):
```json
{
  "title": "Expand security constraints",
  "description": "Add detail about encryption and RBAC enforcement.",
  "status": "todo",
  "priority": "high",
  "assigneeId": "uuid-or-null",
  "dueDate": "2025-08-01",
  "labels": ["docs"],
  "source": {
    "type": "document_selection",
    "documentId": "doc-uuid",
    "anchor": {
      "type": "textQuote",
      "quote": "All sensitive user data stored in the database...",
      "quoteHash": "sha256...",
      "createdFrom": 120,
      "createdTo": 176,
      "headingPath": ["2.4.2", "Security Requirements"]
    }
  }
}
```

Response (201):
```json
{
  "data": {
    "task": { "id": "task-uuid", "title": "Expand security constraints", "status": "todo" },
    "links": [
      {
        "id": "link-uuid",
        "type": "task_document_link",
        "taskId": "task-uuid",
        "documentId": "doc-uuid"
      }
    ]
  }
}
```

Errors:
- `404 DOCUMENT_NOT_FOUND` (if source.documentId invalid)
- `403 FORBIDDEN` (if cannot view document or cannot create tasks)
- `400 INVALID_ANCHOR` (if anchor malformed)
- `400 WORKSPACE_MISMATCH` (document not in same workspace)

---

```json
  }
}
```

## §5.6.10 Data Model (Authoritative)

### v1 Recommendation: dedicated link table (future-proof)

#### `task_document_links`
- `id UUID PK`
- `workspace_id UUID FK`
- `task_id UUID FK`
- `document_id UUID FK`
- `anchor JSONB NULL` (null means “linked to document generally”)
- `created_by UUID FK`
- `created_at TIMESTAMPTZ`
- `deleted_at TIMESTAMPTZ NULL` (soft delete; optional v1.1)

Constraints:
- `task_id` and `document_id` must belong to same workspace (enforced by application logic)
- Unique index optional:
  - allow multiple links per task, even same document if anchors differ
- Indexes:
  - `(workspace_id, task_id, created_at DESC)`
  - `(workspace_id, document_id, created_at DESC)`

> Even if v1 UI supports only “one link per task”, using a table now avoids redesign later.

## §5.6.11 Events

| Event | Trigger | Payload |
|------|---------|---------|
| `task.created_from_document` | task created with source document | `{ workspaceId, taskId, documentId, actorId, linkId }` |
| `task.linked_to_document` | link created | `{ workspaceId, taskId, documentId, linkId }` |
| `task.unlinked_from_document` | link removed (v1.1+) | `{ workspaceId, taskId, linkId }` |

Side effects:
- Activity feed entry (optional P2): “Alice created task from Requirements doc”
- Notifications: none by default (avoid noise). Mentions/assignments still notify.

## §5.6.12 Edge Cases (Must Be Handled)

| Scenario | Expected Behavior |
|---------|-------------------|
| User selects 10,000 chars of text | Quote must be truncated to 280 chars; warn user “Selection truncated for link preview.” |
| Document content changes and quote no longer exists | Deep link opens doc but cannot highlight; show banner: “Linked text moved or changed.” |
| Document deleted | Task still exists; link shows “Document deleted” with no open action. |
| Task deleted | Link is soft-deleted or cascade-deleted. |
| Workspace mismatch | Reject create link with `400 WORKSPACE_MISMATCH`. |
| Viewer tries create task from doc | UI hides action; API returns 403 if forced. |
| Archived workspace | Allow viewing links; disallow new tasks/links due to read-only policy. |
| Academic submitted doc | Selection still possible in read-only; creating task allowed. |

## §5.6.13 Observability

Metrics:
- `task.link.created.count`
- `task.created_from_document.count`
- `document_link.open.count`
- `document_link.anchor_resolved.rate` (client-side analytics; optional)

Logs:
- `task_link_created` (info): workspaceId, taskId, documentId, linkId
- `task_link_denied_permission` (warn)
- `task_link_anchor_invalid` (warn)
- `task_link_workspace_mismatch` (warn)

Privacy:
- Do not log full quote text in production logs (log quoteHash + length only).

## §5.6.14 Testing Requirements

### Unit
- anchor schema validation

### Integration
