## §2.1 Persona Definitions

### §2.1.1 Persona: Student (Academic Context)

| Attribute | Detail |
|-----------|--------|
| **Name** | Student |
| **Context** | Academic workspace mode |
| **Who they are** | Undergraduate or graduate student working on a group project for a course |
| **Goals** | Collaborate with teammates on documents and tasks. Track what they need to do and when. Submit work for supervisor review. Receive and act on feedback. Never lose work. |
| **Frustrations (current state)** | Scattered across 4+ tools (Docs, Trello, Telegram, Drive). Missed task assignments buried in chat. No single view of "what do I need to do today?" Hard to know if teammates have done their part. Submission process is manual and error-prone. Version conflicts with `Final_v2_REAL.docx`. |
| **Technical comfort** | Moderate to High (CS/Engineering students) |
| **Usage frequency** | Daily during project periods, sporadic otherwise |
| **Primary device** | Laptop (Windows/macOS/Linux) |
| **Accessibility needs** | May include keyboard-only users, screen reader users |
| **Typical workspace role** | Member |

**Key scenarios:**
1. Opens CollabSphere in the morning, checks "My Tasks" to see what's assigned to them
2. Opens a shared document, sees teammate editing in real-time, adds their section
3. Moves a task from "In Progress" to "Review" on the Kanban board
4. Receives a notification that the supervisor has requested changes on their submission
5. Searches for a document they worked on last week

### §2.1.2 Persona: Project Lead (Academic or Professional Context)

| Attribute | Detail |
|-----------|--------|
| **Name** | Project Lead |
| **Context** | Both academic and professional workspace modes |
| **Who they are** | In academic context: the student designated as team lead. In professional context: the tech lead or project manager responsible for day-to-day execution. |
| **Goals** | Everything a Member does, PLUS: assign tasks to team members, track overall project progress, ensure deadlines are met, manage day-to-day project operations, generate progress reports. |
| **Frustrations (current state)** | No visibility into who is doing what. Cannot enforce deadlines because there is no central task board. Coordinating across multiple tools is exhausting. Cannot tell if everyone has seen the latest document version. Spends more time managing tools than managing the project. |
| **Technical comfort** | Moderate to High |
| **Usage frequency** | Daily, multiple times per day |
| **Primary device** | Laptop |
| **Typical workspace role** | Manager |

**Key scenarios:**
1. Creates tasks for each team member from the project requirements document
2. Checks the Kanban board to see what is stalled or overdue
3. Reviews a teammate's document section and leaves inline comments
4. Looks at the workspace analytics to prepare a progress update for the supervisor
5. Invites a new team member to the workspace

---

### §2.1.3 Persona: Supervisor (Academic Context)

| Attribute | Detail |
|-----------|--------|
| **Name** | Supervisor |
| **Context** | Academic workspace mode |
| **Who they are** | Faculty member, teaching assistant, or course instructor overseeing one or more student project teams |
| **Goals** | Create and configure workspaces for project teams. Monitor team activity and progress without micromanaging. Review submitted documents and provide structured feedback. Assess individual contribution levels for fair grading. Manage multiple teams efficiently without being overwhelmed. |
| **Frustrations (current state)** | Receives work via email — hard to track across 20+ teams. No way to see who contributed what in group work. Giving feedback requires downloading files, annotating offline, and re-uploading. Cannot see if teams are struggling until it is too late. Status meetings are the only way to get updates, wasting everyone's time. |
| **Technical comfort** | Moderate |
| **Usage frequency** | Several times per week |
| **Primary device** | Laptop/Desktop |
| **Typical workspace role** | Owner |

**Key scenarios:**
1. Creates a workspace using the "Senior Project" template for a new student team
2. Reviews the workspace dashboard to check progress across all their teams
3. Opens a submitted document, reads it, adds inline feedback comments
4. Approves a document or requests changes with specific notes
5. Views the activity log to see individual contribution levels before grading

### §2.1.4 Persona: Developer (Professional Context)

| Attribute | Detail |
|-----------|--------|
| **Name** | Developer |
| **Context** | Professional workspace mode |
| **Who they are** | Software engineer, designer, or other technical contributor working on a product or project |
| **Goals** | Find assigned tasks quickly. Document technical decisions and designs collaboratively. Track sprint progress. Reference project documentation without leaving the workspace. Stay informed about relevant changes without notification overload. |
| **Frustrations (current state)** | Documentation is in Notion but tasks are in Jira and discussions are in Slack. Writing an RFC means copying a template manually every time. Task context is lost because the task description in Jira does not link to the design doc in Notion. Context switching between 5 tools throughout the day is exhausting. |
| **Technical comfort** | Very High |
| **Usage frequency** | All day, every workday |
| **Primary device** | Laptop with large monitor |
| **Typical workspace role** | Member |

**Key scenarios:**
1. Presses Cmd+K to open command palette, types "auth RFC" to find the authentication design document
2. Creates a new task from within a document by selecting text and choosing "Create task from selection"
3. Drags a task from "In Progress" to "Review" after pushing their code
4. Opens the sprint board to see what is left to do before the sprint ends
5. Exports a technical document to Markdown for inclusion in the GitHub repository

### §2.1.5 Persona: Engineering Manager (Professional Context)

| Attribute | Detail |
|-----------|--------|
| **Name** | Engineering Manager |
| **Context** | Professional workspace mode |
| **Who they are** | Technical manager responsible for team health, project delivery, and process. May also be the workspace creator. |
| **Goals** | Oversee project progress across the team. Ensure documentation standards are maintained. Manage team membership and permissions. Track velocity and identify blockers. Onboard new team members efficiently. |
| **Frustrations (current state)** | No unified view of documentation status plus task progress. Onboarding a new engineer means giving them access to 6 different tools. Cannot easily audit who has access to what. |
| **Technical comfort** | High |
| **Usage frequency** | Daily |
| **Primary device** | Laptop |
| **Typical workspace role** | Admin or Owner |

**Key scenarios:**
1. Creates a workspace using the "Software Development Project" template
2. Invites team members with appropriate roles (developers as Members, tech lead as Manager)
3. Reviews the workspace analytics dashboard before the weekly standup
4. Adjusts workspace settings or member roles as the team evolves
5. Uses the activity feed to understand what happened while they were in meetings

---

### §2.1.6 Persona: Platform Administrator

| Attribute | Detail |
|-----------|--------|
| **Name** | Platform Admin |
| **Context** | System-wide, not workspace-specific |
| **Who they are** | IT staff, platform operator, or the person managing the CollabSphere instance (could be one of the founders initially) |
| **Goals** | Manage users across the platform (create, deactivate, reset passwords). Oversee all workspaces. Monitor system health and usage. Configure platform-wide settings. Handle support escalations. |
| **Frustrations (current state)** | Needs to do this alongside other responsibilities. Wants self-service features to minimize manual intervention. Needs clear audit trails for security compliance. |
| **Technical comfort** | High |
| **Usage frequency** | Weekly or on-demand |
| **Primary device** | Desktop |
| **Global role** | Admin |

**Key scenarios:**
1. Searches for a user by email to investigate a support request
2. Deactivates a user account that violates terms of service
3. Views the admin dashboard to check active user counts and storage usage
4. Reviews the audit log for suspicious activity (failed logins, permission changes)
5. Resets a password for a user who lost access to their email

---

### §2.1.7 Persona: System (Non-Human)

| Attribute | Detail |
|-----------|--------|
| **Name** | System |
| **Context** | Background processes, scheduled jobs, event handlers |
| **Who they are** | Automated processes that perform actions without direct user interaction |
| **Actions** | Dispatch notifications on events. Send email digests. Clean up expired data (soft-deleted records past retention). Process file uploads (thumbnails, virus scanning). Generate activity log entries. Send deadline reminders. Purge expired invitation tokens. Invalidate expired sessions. |
| **Used in stories where** | The trigger is automatic, not user-initiated |
