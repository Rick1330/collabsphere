## §2.2 Role Architecture

### §2.2.1 Two-Level Role System

CollabSphere uses a two-level role system to separate platform-wide permissions from workspace-specific permissions.

**Level 1: Global Role (on the User entity)**

This determines what a user can do at the platform level, outside of any specific workspace.

| Global Role | Description | Who Gets This |
|-------------|-------------|---------------|
| `USER` | Regular authenticated user. Can create workspaces, join workspaces, manage their own profile. | Everyone by default |
| `ADMIN` | Platform administrator. Can manage all users, view all workspaces, access admin dashboard, view audit logs. | IT staff, platform operators |

**Level 2: Workspace Role (on the WorkspaceMember entity)**

This determines what a user can do within a specific workspace. A user can have different roles in different workspaces.

| Workspace Role | Level | Description |
|----------------|-------|-------------|
| `OWNER` | 5 | Created the workspace. Full control. Can delete workspace, transfer ownership. Exactly one owner per workspace at all times. |
| `ADMIN` | 4 | Can manage members, change workspace settings, manage templates. Cannot delete workspace or transfer ownership. |
| `MANAGER` | 3 | Can assign tasks, review submissions, view analytics, manage content organization. Cannot manage members or workspace settings. |
| `MEMBER` | 2 | Can create and edit documents, create and work on tasks, post comments. The standard "contributor" role. |
| `VIEWER` | 1 | Read-only access to workspace content. Can view documents and tasks. Can post comments where allowed. Cannot create or edit content. |

### §2.2.2 Role Assignment Rules

1. **A user can have different workspace roles in different workspaces.** Example: Alice is a Member in Workspace A but a Manager in Workspace B.
2. **Global role and workspace role are independent.** A Platform Admin does NOT automatically get Owner/Admin access to all workspaces. The admin dashboard lets them VIEW all workspaces for management purposes, but to actually participate in a workspace, they must be added as a member with an explicit workspace role.
3. **Every workspace has exactly one Owner.** The Owner cannot leave the workspace, delete their account while owning a workspace, or demote themselves — unless they first transfer ownership to another member with Admin or Manager role.
4. **Ownership transfer** is possible: Owner can transfer ownership to any member who has Admin or Manager role. After transfer, the original owner becomes Admin.
5. **Role hierarchy is strict.** A higher role inherits all permissions of lower roles. Owner can do everything Admin can do. Admin can do everything Manager can do. And so on.
6. **Workspace role is per-membership**, not global. The workspace_members table stores the role for each user-workspace combination.
7. **Self-demotion** is allowed (Admin can make themselves Member) UNLESS it would leave the workspace with no Admin+ members. The system must always have at least the Owner.
8. **Invitation role.** When inviting a new member, the inviter specifies the role. The minimum role is Viewer. The maximum role an inviter can assign is one level below their own role (Admin can invite up to Manager, Manager can invite up to Member, etc.). Exception: Owner can invite at any role including Admin.
