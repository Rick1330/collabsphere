## §2.4 Role Mapping by Workspace Type

When a workspace is created, the creator selects a workspace type. The type determines which role labels are shown in the UI (cosmetic) and which features are enabled (functional). The underlying permission system is identical.

| Workspace Type | Owner Label | Admin Label | Manager Label | Member Label | Viewer Label | Special Features |
|----------------|------------|------------|--------------|-------------|-------------|-----------------|
| **Professional** | Owner | Admin | Tech Lead | Developer | Stakeholder | Sprint boards, dev templates, velocity tracking |
| **Academic** | Supervisor | Teaching Assistant | Project Lead | Student | Reviewer | Submission workflow, review/approve, contribution tracking, academic templates |
| **General** | Owner | Admin | Manager | Member | Viewer | No special features, all defaults |

Note: These are **display labels only**. The underlying role is always Owner/Admin/Manager/Member/Viewer. The label mapping is stored in workspace settings and can be customized by the Owner.
