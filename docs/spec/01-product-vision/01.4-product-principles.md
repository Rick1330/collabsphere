## §1.4 Product Principles

These principles guide every design and engineering decision:

1. **Workspace-first.** Everything is scoped to a workspace. No data leaks between workspaces. A workspace is the atomic unit of collaboration.
2. **Collaboration-native.** Real-time collaboration is the default, not a bolted-on feature. Multiple people editing the same document is the expected workflow, not an edge case.
3. **Context flows automatically.** Creating a task from a document section links them permanently. Completing a task updates the project dashboard. Commenting on a document triggers a notification. The system connects the dots so humans don't have to.
4. **Roles match reality.** The permission system understands that a student is not a supervisor, a developer is not a project manager, and a viewer is not an editor. Roles are meaningful, not cosmetic.
5. **Templates accelerate work.** No team should start from a blank canvas. Pre-built templates for common project types provide structure, standards, and best practices out of the box.
6. **Keyboard-driven speed.** Power users should be able to navigate the entire application without touching a mouse. Command palette, keyboard shortcuts, and quick actions are first-class features.
7. **Integration-ready architecture.** The system is built with an event-driven internal architecture so that future integrations (Slack, GitHub, webhooks) can be added without modifying existing code.
8. **Open and extensible.** CollabSphere is designed to grow with its community. The architecture supports contributors, the documentation enables onboarding, and the template system allows community-created content.
