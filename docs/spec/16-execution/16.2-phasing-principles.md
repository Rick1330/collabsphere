## §16.2 Phasing Principles

1. **Ship vertical slices early**  
   Build end-to-end flows (UI + API + DB) rather than “all backend first”.

2. **De-risk CRDT collaboration early**  
   Integrating Tiptap + Yjs + Hocuspocus is the highest technical risk; do it early to avoid late surprises.

3. **Lock down RBAC and workspace isolation early**  
   Security bugs become expensive later. Build and test guards early.

4. **Minimize scope creep**  
   v1 must focus on the core product loop:
   - create/join workspace → create docs/tasks → collaborate → review (academic) → notifications

5. **Build for contributors**  
   Clean module boundaries, consistent patterns, and high-quality docs reduce future onboarding time.
